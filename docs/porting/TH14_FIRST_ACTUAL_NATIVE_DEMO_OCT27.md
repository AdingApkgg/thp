## 加载时序定位

第二份在原版主资源泵 `47d720` 上另记录了 287 次实际入口，观察自机 9、背景 4、标题 6 和 ECL 10／11 的资源游标。原版在自机对象创建后，仍会等待后续资源的 worker 发布；部分队列存在多个主帧的等待。

实际 C++ 的只读加载观察运行至首个三面 tick，共 2,024 帧。13／5／2／3／16 个纹理块分别属于上述五项资源；自机在 Application 1998 帧可见。当前 `GameResources::load_stage` 预先同步读取场景、HUD、ECL 和它们的 ANM，随后 Application 仅按纹理队列推进。原版自机已存在时仍进行后续读取和唤醒，因此加载模型与异步交付边界是下一项调查范围；尚未以这些观察唯一归因每个差异。

原版 `47d260` 先将上传游标减一后再比较条目索引。游标从 1 开始，不能把资源泵入口的 `0..N` 误读为多一个纹理或固定的额外结束拍。两份实际年龄差为 5／6，也拒绝固定增加五拍的修补；未补计数、重置 RNG、写回动画或修改图像。

GLES 通用 CPU 近／远面裁剪的私有实验另保留为失败：21 幅 Stage 中仍为 20 幅相同，原来的一个字节差增加至 48 个，未集成生产代码。
