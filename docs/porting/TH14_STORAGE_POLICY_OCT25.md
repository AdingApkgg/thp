# TH14 测试存储约束 · 2026-10-25

磁盘空间优先于新增大体积采样。清理时已停止原版采样与自动接续；用户要求继续后，仅按需恢复带空间检查和单次限额的采样，不恢复无上限接续队列。

历史数据的逻辑大小约为：`artifacts/th14` 234GiB，TH14 多版运行与预览产物 99GiB。反复复制游戏资源、字体、音乐、完整轨迹及构建版本是主要来源。目录统计可能重复计算硬链接，应同时观察卷的实际可用空间。

后续规则：

- 原版程序、音乐、归档等固定输入通过 [th14-test-storage.py](../../tools/th14-test-storage.py) 的只读内容缓存复用。缓存使用测试副本；原作目录保持独立，不与缓存建立硬链接。
- TH14 新运行包、预览包的大文件通过 [th14-immutable-artifacts.mjs](../../tools/th14-immutable-artifacts.mjs) 共享相同内容。保留版本路径、清单及文件哈希，不再为同一份音乐、字体和资源创建完整副本。
- 可配置采样器默认保留至少 100GiB 可用空间，单次观察数据上限 2GiB；启动前和采样期间检查，超限结束该采样并记录 `storage-limit.json`。游戏文件的共享副本不计入单次观察数据。
- 默认只追踪前 1000 次回调的动画发布，后续检查保留逐回调选定状态和有界对象快照。需要更大范围时，先确定数据预算和复用方式。
- 保留源码、原作、录像、失败记录和关键验证数据。旧原始数据优先使用透明 NTFS 无损压缩；不通过删除失败结果来缩小体积。

本次处理的具体路径、内容 SHA256、去重和压缩记录保存在 `artifacts/th14/storage-audit-oct25/`。去重后已复核当前运行包 40 个文件的 SHA256，并检查原作 EXE 和共享测试副本仍为独立文件。
