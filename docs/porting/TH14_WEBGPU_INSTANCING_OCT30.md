# TH14 WebGPU 实例批次合入与有限验收 · 2026-10-30

WebGPU 现保留 C++ Renderer 已合并的实例批次，避免将每个实例再次拆成单独绘制。私有候选通过下列对照后，五份实现已合入工作区；正式工具构建的原生 Application、Renderer 组件及 Asyncify 组件与实际测试的候选逐字节一致。GLES Application 也重新构建，全部 Wasm 字节与此前已验收版本相同。玩法核心未改；146 单元完整浏览器产物已重建，普通启动、标题、三面自然演示及普通自机选择已观察，不能把组件测试或这些有限 UI 观察称为完整浏览器验收。

## 实际有限对照

| 范围 | WASI／原生 GPU | Emscripten／Asyncify／JavaScript GPU |
| --- | --- | --- |
| 留存 Stage 原版 D3D9 参考 | 21／21 完整 BGRA 缓冲一致 | 同一 21／21 一致 |
| 新声明的独立 D3D9 控制 | 8／8 完整缓冲一致 | 同一 8／8 一致 |
| Stage 绘制提交 | 原 1,005 次输入变为 630 次提交 | 实际也是 630 次 |
| 合成控制绘制提交 | 原 3,128 次输入变为 9 次提交 | 实际也是 9 次 |

合成输入不含游戏资源，使用实际独立 D3D9 HAL 生成参考。实例数分别为 1、2、3、17、1023、1024、1025、33，覆盖单实例旧路径、批次上限和拆批后的单实例。每个实例有不同的世界矩阵／颜色因子，部分控制含雾、BlendFactorAlpha、偏移子视口和跨近裁剪面。全部四通道及完整覆盖均保留，没有容差或只检查目标像素。

实际 C++ Application 使用当前 57a 的 141 个游戏核心对象，分别运行串行基线与私有候选各 2,264 帧、21 项断言。从冷标题以归一化普通菜单输入选择灵梦 B Normal 录像，496 行完整所选状态日志、两处图像、活动 VM 输出、文件及 1,508,352 帧静音 PCM 累计哈希相同。候选只重编 Renderer 对象并复用逐哈希核对的四个设备／夹具对象。

该窗口的绘制提交从 225,938 次降至 82,420 次，减少约 63.5%。两次实际进程墙钟分别为 54.89 秒和 27.00 秒；这是有其他测试同时运行时的一次成对测量，不是稳定浏览器 FPS 或普遍加速比证明。物理音频设备均为零，原版普通 GUI、整局原版画面／PCM和独立 worker 交错没有据此验收。

## 实现范围

候选只合并已有的、顶点相同的 WorldUv 四边形批次，保留原顺序；单实例、其他拓扑、索引和纹理反馈路径继续串行处理。每条记录为 148 字节，包含由 C++ 按已有次序计算的 clip／eye 矩阵、原颜色因子和原投影资格。没有将矩阵组合改到 GPU，也没有传入原版计算结果。

WGSL 使用单独实例入口，并将颜色因子按 flat varying 传入片元，保留原逐次绘制时 uniform 因子的语义。两个宿主分别绑定实例步进顶点缓冲；桥接同步复制 GPU 输入，没有新增等待、额外异步栈、游戏时钟或原版值补偿。单批上限仍为 1,024；没有请求可选 GPU 特性。
