# TH14 冷启动公共 ANM 后台解析

2026-10-29。原来冷启动的任务虽逐项排队，`front.anm`、`bullet.anm`、`effect.anm`、`title.anm`、`title_v.anm` 的 CPU 解压及解析仍在主线程回调执行。现在这些任务接到既有独立 worker，使用同一个生产 ANM 解析器与有界数据包；回调获得所有权后仍由主线程执行 GPU 上传和模板准备。既有文件顺序、代际失效检查、上传等待及标题发布保持原路径，没有加入固定帧补偿。

基线为 `1c9995853ba9d458810b77e03dca1d3b26ab1678`。只重编 Application 一个单元，另外 145 个对象经哈希核对复用；worker 的全部文件与此前 STD／ECL 构建逐字相同。主 Wasm 为 2,744,264 字节，SHA-256 `9f5c125f11eddd19947b352a274554923cf5893fceedaa063df14e18b8de5fdf`。139 路由／27 项 HTTP 及实际服务字节通过，生成字体和音乐继续使用已有别名。

对当前实际 worker 重新构建 C++ 导入器，全部 57 个 ANM 的纹理、精灵浮点位、转换脚本及共 245,717,904 个包字节与直接解析相同，包含上述五个冷启动文件。68 个损坏包拒绝并保留目标。检查器只将请求项计入原始归档清单一次，额外交付的 ECL 包含项由其独立闭包控制验证。

实际 Chromium 156／Windows 静音页面观察到标题、自动演示和正常菜单。另用测试专用响应层故意拒绝 `front.anm`：主 Wasm 完全不变，实际 C++ 流程在加载画面明确报出 `TH14 background boot resource decode failed`，没有回主线程解析后继续。注入只改变测试目录的一份 worker 源码及哈希元数据，生产文件未改。恢复未注入的 worker、核对服务字节并整页重载后，再次观察标题，Normal 灵梦 A 717 帧片段自然结束并返回 Replay 列表，所选 HUD 为 3100 分／1 残机／1.03 火力／2 Graze。最终预览已恢复正常版本。

[机器复核摘要](th14-boot-worker-verified-oct29.json)绑定唯一变化的单元、其余对象、当前 ANM 组件、真实错误与恢复的界面证据。这是有限启动／失败／恢复用例，不继承此前不同模块的整段浏览器回放，不宣称原版线程时序、完整状态、像素或音频相同。

`sig`／`ascii`／`text` 的最早资源读取、自机首次选择、其余核心准备及后续换关尚未全部接入独立 CPU worker；原版标题另一历史的 RNG／对象差异、全部模式及整作 1:1 继续。只发布源码、工具与哈希元数据，原版资源和截图留在本机。测试和预览静音，`completeGame=false`、`nativeEquivalent=false`。
