# TH14 后续关卡按 ANM 块上传（2026-10-15）

整作 1:1 未完成。本轮修正后续关卡 SDL 上传队列的工作粒度：每次普通 tick 只准备一个 ANM 资源块，最后一块完成后才允许结束该资源阶段。首次进入关卡与启动核心资源的 boot 队列未在本轮修改。

## 原码依据

二面 `st02logo.anm` 已由原始资源线程解码，完整 362,096 字节与独立解密／LZSS 实现相同。原始 `47d720` 每次只调用一次 `47d230`；`4448cd` 的调用点在成功处理后继续当前普通帧，错误才返回。单个文件的两个 ANM 块需要两次处理。

新实验从同一完整私有暂停状态调用原始 `47d230`，使用保存的主线程 CPU／FS 和明确声明的独立栈。第一轮首先在真实 `D3DXCreateTexture` 请求前停止；后续仅执行捕获的用户态 PE 代码时，走到 Windows 内核查询边界，未调用实际设备或内核服务。

另一组明确声明的 CPU 贴图模型提供尺寸、格式、表面引用和上传参数的成功输出。它不执行滤波或像素上传，不证明物理 D3D 成功。在这一环境中，25,281 次代码观察后，两次原始 helper 调用完整返回：文件进度由原码 `47d2bd` 写为 2，再由 `47d402` 写为 0；七个动画模板完成初始化。没有由宿主代写进度。它仍是显式 helper 调用，不是主线程普通帧续行，等待中的资源线程也没有恢复。

## 生产修正与验证

- `StageUploadsTh14` 为当前资源保留块游标，只有最后一块成功才前进到下一资源。失败和取消仍保留原有归属规则。
- `GraphicsDevice::preload_chunk` 只处理请求的下一块；已有块可重复查询，跳块请求失败。同步 `preload` 能补齐部分资源，失败时释放已持有的纹理。
- `Application` 的后续关卡上传仍继续当前普通 session／draw，不添加额外 ANM update 或成功早退。

真实队列、实际提取的图形设备方法与真实 `TextureImage`／`ImageResample` 转换通过 41 项检查，失败为零。上传后端在这些检查中只记录调用。三个受影响的 SDL 编译单元重新编译，其余对象逐个绑定既有 SHA；共享图形源的 TH13／TH16 分支也通过编译。新 release 的导入／导出接口未改变。
