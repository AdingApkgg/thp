# TH14：后续换关资源的后台解析所有权

此前首次进入关卡已经使用独立 CPU worker，但第二至六关的 HUD、背景 STD／ANM 和 ECL 仍由 `advance_stage_phase` 同步加载。本次为这些后续阶段接入同一独立解析器，保留 HUD → 背景 → ECL 的既有阶段顺序、GPU 请求和模板完成边界。

`StageDecodeTh14` 保存源、关卡所有者、阶段、依赖步骤和递增代数。ECL 先交付计划，再逐份请求实际 ANIM 依赖，最后完成独立敌机资源所有者。回调在解引用资源前检查代数；暂停使旧任务失效，恢复重新请求尚未完成的一步。`cancel_stage_loading` 在第一份 GPU 请求尚未发生时也取消 CPU 所有权。背景所有者发布只是移动 `unique_ptr`，其地址保持稳定。

普通同步消费者仍使用原来的读取路径。SHT 解析、已解析数据的导入／链接、GPU 上传和 ANM 模板创建仍有调用线程上的工作；本次不声称所有加载计算已迁移，也没有加入固定帧补偿。

已完成的有限对照：

- 第二至六关 × 六种自机，共 **30 组**实际独立 worker 对照；STD、ANM、ECL、对话、动态动画及独立所有者的全部所列字段和字节相同。另 **30 组**同步调用路径通过。
- **203 个**实际 worker 批次、**468 次**资源导入。**16 项**控制覆盖各阶段的 GPU 前取消、过期回调、发布背景后的所有者、暂停恢复、失败批次、错误所有者、五类损坏包，以及 GPU 等待期间不重复解码或请求。
- 头文件变化后完整重编 **146 个**浏览器单元和同一冻结源码的 **141 个**原生核心单元；正确的发布版 ResourceCrypt 保持冻结，排除工作区无关改动。
- GLES／WebGPU 新的实际 Application 运行各 **2,264 帧／7 项断言**。两幅完整画面、339 个 VM、状态、RNG、文件以及各 **1,508,352 帧**静音 PCM 与此前相同。该原生 Application 宿主关闭 archive-worker；独立 CPU 控制通过生产关卡控制器和真实资源对象另测，不冒充完整 Application worker 运行。
- 新候选 **139 条路由／27 项 HTTP**检查通过。实际浏览器换关、响应层拒绝及恢复结果由下列独立复算摘要绑定。

实际 Chromium 156 静音页面从普通 Replay 菜单选择 `Deam` 咲夜 B Hard 五面，实际进入六面并继续战斗。随后保持相同主 Wasm，仅在测试响应层拒绝 `st06logo.anm`；重新从五面运行到换关时，实际 C++ 明确报出 `TH14 background stage resource decode failed`。错误前缀的 `last_resource` 仍显示此前五面的最后资源，不能用它判断被拒绝的文件；拒绝目标由唯一测试注入及实际服务字节绑定。故障服务已停止，正常 worker 的实际服务字节复核一致；整页重载后普通启动再次进入标题。
