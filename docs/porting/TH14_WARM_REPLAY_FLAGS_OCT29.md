# TH14 暖启动比较夹具的演示标志

新选取的魔理沙 A Easy 原始录像，在第 662 次 Player 回调暴露了比较夹具的初始化错误。原版观察器在首次 Player 入口声明只清除全局 attract 位 `0x40`；夹具此前只将两个 `demo` 布尔值设为假，漏掉 ECL 与符卡视觉读取的 `enemy_commands.th14_run_flags`。ECL554 因此仍跳过关卡标题家族。

修正仅在夹具已经声明的暖启动边界清除同一位，保留其他位。生产玩法、自机、录像输入和调度器均未改动。旧失败输出保留：初始动画创建在序号 1,801 首次不一致，缺失 file6 的脚本 4、3、5、6、0；首 2,400 回调的战斗采样有 120 字动画句柄差。原有状态、相机与 HUD 相等不能掩盖该失败。

修正后的独立核心复用哈希逐一核对的 141 个生产对象，只重新链接夹具。新输入前 30,000 回调的状态 32 字、相机 25 字、HUD 两字相同；两处快照共 431 个活动 VM，各 303 字及注册顺序相同；162 个战斗检查点、初始 2,870 次原始句柄／文件／脚本发布顺序相同。该前缀实际覆盖一、二面，包含观测到的二面资源就绪及 Scene 交付边界。

延长到 48,000 回调的严格比较仍失败，原始输出保留。首差在回调 30,991、三面换关 frame0 的脚本 RNG 种子：原版 56,097、核心 5,435，当时调用数同为 953,620。原版 `456133` 的种子恢复观察发生在前一 Player 边界之后，主线程当时位于 `4041a0`；从录像头种子推导，两值分别对应 46 与 22 次递推。这提示现有整回调交付边界仍不足以表达实际线程时序，尚未据此验收具体子回调位置，未把这些诊断值传入引擎或加入固定帧补偿。30,000 的通过前缀不能覆盖此失败。

比较器另修正第一关前缀尚无换关事件文件时的读取：只有所采行全部仍为第一关，才允许对应文件尚未生成。两面及以后继续要求原有事件文件，不用空事件代替。由原始采集复制的显式 2,400 回调前缀在 `observed` 调度下通过，复制过程没有启动新原版进程。

可用 `python -X utf8 tools/th14-warm-replay-flags-evidence-oct29.py --check` 重新计算[所选证据](th14-warm-replay-flags-verified-oct29.json)。原版观察仍在继续时，状态、相机和 HUD 的绑定明确只覆盖前缀字节；检查点索引绑定的是截至 30,000 回调的规范投影，后续追加不会被误称为已验证。

这不是原版普通菜单初始化、自然结束、全六面、完整 GPU／原版 PCM 或全部模式验收。旧冻结夹具结果保留各自范围，不自动继承给修正后的夹具。30／25 的既有模式覆盖统计在新完整采集核实前保持不变。

本份原版观察随后于 80,324 回调、五面自然提前结束，进程已退出、错误为空。实际进入一至五面，比旧输入的一至三面多出四、五面；六面入口仍缺失，30／25 的模式组合统计保持不变。该自然终止不覆盖上述 48,000 回调严格失败，也不把 30,000 的通过前缀延伸到整段。
