# TH14 活动关卡的初始化覆盖与异常清单（2026-11-03）

旧版初始化时间检查器 v2 会核对每个报告出的 `0x456133` 事件和模型输入，但它以已有事件列表作为预期集合。若第二面已经实际推进，而原版事件和模型输入同时遗漏，两个空集合仍可通过。合成两回调反例复现了这个问题；这不表示已有记录发生了遗漏。

新增 [v3 检查器](../../tools/th14-verify-native-initialize-timing-v3-nov03.py)读取并哈希核对原版所选状态：除了首个实际观察到的关卡，每个已出现正关卡帧的后续关卡都必须有对应原版初始化事件和模型输入，然后再执行原有 v2 时间绑定。它拒绝关卡倒退／重入，因为该情形需要单独的事件模型；仅进入但始终为零帧的关卡也不属于本检查的保证范围。以 Extra 为首个且唯一关卡的正控制可通过，遗漏事件／输入与关卡倒退的负控制均被拒绝。

16 份既有回归的时间部分重新执行后均通过；其中灵梦 B Easy 的原版报告仍含 12 个首次机会异常，所以这一结论**没有**通过异常门槛。新增[组合入口](../../tools/th14-verify-native-campaign-exceptions-timing-v3-nov03.py)依次检查异常、v3 时间及既有字段复算；魔理沙 A Normal 的 66,909 回调通过组合检查，含异常的 Hard 前缀在写出通过证明前被拒绝。结果和具体范围绑定在[机器可读证据](th14-initialize-active-stage-nov03.json)。

另外，重新哈希并逐回调读取[模式清单](th14-mode-acceptance-inventory-nov03.json)中 46 份原版记录：45 份无报告异常，30 组各有至少一份无异常记录，其中 28 组各有一份无异常记录观察到该组全部目标关卡入口。剩余是魔理沙 A Normal、Hard 的第六面。灵梦 B Easy 的无异常替代记录没有完整字段比较证明，不能用入口覆盖替代玩法通过；源录像 EOF 及整局等价也不由这个统计证明。检查器与范围见[清单异常复核](th14-mode-debug-exception-audit-nov03.json)。

本轮只增加验收工具，没有改变生产玩法。异常成因、原版真实线程交错、完整玩法／图像／音频、普通界面和浏览器仍需继续完成。
