# TH14：多窗口保存改为逐文件提交（2026-10-16）

同源旧游戏窗口的文件系统不知道后来导入的录像。原 `IDBFS.syncfs(false)` 对整个目录做同步，会把这些新文件当作已删除文件清理。实际预览中，新导入的魔理沙 B 录像曾在刷新后消失；九项隔离浏览器测试中的第一项也用未改动的真实 IDBFS 重现了删除。

本次只改变 TH14 浏览器存储外壳。`browser-save-delta.mjs` 在首次读取后保留文件基线，保存时只提交当前窗口确实改变或删除的文件，不重写未改动的旧副本。比较覆盖文件模式、链接与完整内容，不依赖时间戳。同一个 IndexedDB 事务在替换、删除前核对远端版本；其他窗口已修改同一槽位时，整个事务中止并报告冲突。失败不会推进基线，导入／删除命令还原本地文件及原有时间与模式，后续可以重试。空闲录像管理重新读取持久化目录；运行中的游戏保留自己的文件系统与帧时序。

实际浏览器测试使用两个真实 SDL/Emscripten 文件系统、原有 IDBFS 与一个新 UUID 数据库；不运行游戏帧、绘制或音频，也不访问已有存档。九项全部通过：原始全树删除负对照、旧窗口保存保留新录像、未变旧成绩不覆盖新成绩、同槽冲突全事务回滚、已删除文件不复活、相同时间戳的不同内容正常保存、过时删除不清除远端新版本、真实事务主动 abort 后重试，以及提交期间的新本地改动串行保存。abort 是明确注入的事务中止，没有称为实际容量不足。测试源码发布为 [浏览器夹具](../../tools/th14-save-delta-browser-check-oct16.mjs) 与 [页面](../../tools/th14-save-delta-check-oct16.html)，导入的 `th11.mjs`、`th11.wasm`、`delta.mjs` 由私有诊断清单分别映射到冻结 SDL 模块及被测 helper。

另用固定 `http://localhost:8208/` 的两个实际 Launcher/Runtime 窗口验证：第一个游戏窗口先启动，第二个导入完整公开咲夜 B 录像为 `th14_ud0001.rpy`，列表从两份增至三份。第一个窗口保持运行，第二个经过两次完整页面刷新后，旧 `th14_01.rpy`、`th14_ud0000.rpy` 与新 `th14_ud0001.rpy` 均保留；两个窗口没有新警告或错误，静音标记均在。时间与完整界面原文绑定到收据。没有额外插桩统计实际定时同步调用，本次新文件也没有再次导出做字节比较；持久内容的精确读回由上述隔离测试覆盖，实际窗口证据只声称列表／大小和刷新保留。

游戏 WASM 仍是已发布版本 `7e42a509065676ece981f2e8e5e7ce9a86d2960d02149398b1c0c0316c15f088`，1,892,012 字节，C++ 未在本次重编译。打包重新核对冻结 SDL 构建的全部源码、头文件与对象，复用冻结 Launcher；127 个站点路径中仅 `app-shell-sw.js`、`runtime/th14/runtime-files.json`、`runtime/th14/shell.mjs` 改变，另重写散列清单。当前共享工作区已有独立源码改动，故明确使用 `--frozen-release-snapshot`，报告中的当前工作区源码已验证字段保持 false；没有覆盖或夹带该改动。

本机预览外层与内层继续默认静音，存档来源和现有数据保留。发布包音频逻辑未变。此修复不能让已加载旧外壳的窗口自动获得新存储实现；部署后仍应完整重新打开旧窗口。同槽位冲突采用报错保留远端，不自动合并成绩或录像。
