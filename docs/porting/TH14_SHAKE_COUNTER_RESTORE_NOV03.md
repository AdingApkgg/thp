# TH14 震屏随机计数碰撞修复

分阶段震屏执行两次随机数调用时，加载线程可能在首次随机数读取前把视觉随机数计数清零。计数先为 4、两次调用后仍为 4 时，以前用“前后计数不同”判断是否产生随机数会漏掉实际调用，使控制器复用的栈字错误。现在直接记录本次震屏是否调用了随机数，并保留最后一次实际返回值；每个震屏效果单独初始化标志。

原版指令对照执行了 2,016 组回调配置，其中 480 组发生了随机调用并实际执行原版 worker 的 `456129` 计数清零指令；调度点与输入是声明的合成交错，不是对某次历史线程执行顺序的证明。480 组 C++ 组件比较中，旧实现有 192 个栈字错误，修复后为零。独立复核覆盖重建二进制、每次恢复 36 项处理器状态、每版本 312 组效果生命周期及 192 组可选输出参数组合。

当前修复仅涉及 `ScreenShake.hpp` 与 `ScreenShake.cpp`，141 个核心对象重编，普通 134 项导出保持一致。16 份已有自然结束记录共 1,579,705 回调严格及独立通过；TH12、TH13、TH14、TH16 共 12 项语法检查通过。[证据与版本绑定](th14-shake-counter-restore-nov03.json)。

这不证明完整原版 worker／控制器读取路径、历史线程顺序或整作等价。旧 36,826 回调样本仍有随机种子／计数差异，新核心的完整 Application 和浏览器验收需要重新进行；其他未完成模式、原版普通 GUI、原版整局像素／PCM、指针、相机及独立调度继续开放。测试静音，整作 1:1 未完成。
