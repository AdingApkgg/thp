# TH14 首次可玩画面的背景 UV 因果对照 · 2026-11-12

当前生产游戏源码仍为 `e6b15d27768ee4da293c81c3c239e3d42880020b`。本轮把首次可玩画面的大范围差异定位到加载期间持续推进的背景 UV，并保留所有实际严格失败。没有将原版 UV、年龄、计数或就绪帧写进生产引擎，也没有修改运行包来凑图。

## 活动注册表与未注册 VM 分开检查

首先离线比较已经收回的当前首次 Present 与同一启动 profile 的原版参考。原版活动注册表有 77 个 VM，当前旧采集有 76 个；73 个原始数值句柄相同，其中 48 个却属于不同 file/script。原始句柄和注册顺序没有重映射。22,119 个可比较字中有 1,153 字不同，严格失败；全部 Native 指针链接均能由捕获的注册节点 self 指针解析，未把未知链接填零。

完整 file/script 数量清单只有一项计数不同：原版 `ascii:16` 有 21 个粒子，C++ 有 20 个。它会影响后续分配序号，不能把相同句柄直接当成相同动画，更不能将 1,153 个字全部解释成渲染器错误。

还核对了活动注册表以外的状态。原版 type0 geometry 从偏移 0 开始包含五个 1,484 字节 VM，最后 `+0x1cfc/+0x1d00` 才是 state/counter；初次临时解读把前八字节当头部的结果未用于正式比较。前四个 VM 的全部 303 项表示逐字相同，第五个 `effect:195` 只差六项：重复表示的年龄字段和两个 UV 滚动位置。四个合成 VM 的 204 项已测展开字段相同；没有将其升级为未采集的全部合成状态通过。

旧病例的 type0 counter 为原版 84／C++ 81。过场根 VM 的已测绘制字段没有差异，根年龄仍不同。

## 原版解释器验证三个更新的局部转换

在私有 Unicorn 中加载真实 `effect.anm` 与 ASCII fallback，执行原版加载器、脚本拷贝及 `46fe50` 解释器。以真实捕获的第五个 VM 为克隆输入，保留未测 opaque 字，仅将脚本与资源指针重新绑定到相同已加载资源；捕获的 sprite 指针保持原值，并替换 C++ 观察中不同的五个物理字段。克隆在执行前的全部 303 项均与对应 C++ 观察值相同；这不是恢复完整原版线程前史。

原版实际执行三次更新后，全部 303 项与原版捕获值相同。两次、四次，以及三次但速率为 0、0.5、1.5、2 的控制均不相同；八例均正常返回，RNG 保持不变。它证明此局部解释器转换足以产生旧病例的年龄／UV 差异，不证明实际缺少的线程调用唯一来自某个函数，也不授权给运行引擎补三帧。

首次组件准备在首个被测克隆更新前因 Unicorn 不接受 `bytearray` 而退出；失败源码和记录保留，转为 `bytes` 后使用新目录执行。没有为改变比较结果重跑原版 OS 游戏。

## 实际 GPU 的重复／替换／恢复控制

重新链接私有绘制诊断模块 `e652ec8e1bc26f18adeb1334d1c28e75543c88a06a4a4d785107d4ce1ca51cd5`。141 个游戏和 4 个宿主正常权限提供者逐项重新校验复用；Application 沿用当前已核验的冻结只读观察版本，只有诊断夹具放宽访问权限。

实际会话 97015／PID 41220 只运行一次冷启动、真实菜单 Replay No.1 入场，到 508 个宿主帧／第一个 Player 后停止游戏更新。保留真实 ANGLE GPU，使用实际 session 绘制、原帧文字和实际纹理，依次执行：

| 绘制 | 操作 | 相对原版完整 BGRA 的差异像素 |
| --- | --- | ---: |
| 实际首次画面 | 原引擎自然状态 | 197,624 |
| 重复控制 | 不更新、不改状态，再绘制 | 197,624，且与实际图逐字节相同 |
| 诊断反事实 | 仅替换 `effect:195` 的两个 UV 字段，再绘制 | 11,694 |
| 恢复控制 | 恢复原 UV，再绘制 | 197,624，且与实际图逐字节相同 |

这个诊断只在实际首帧停止后读取原版 UV，之后不再恢复游戏更新。没有将原版像素或每帧状态送进实际冷启动／游玩路径。各次绘制的 Player、关卡帧、counter、年龄、SCRIPT 和游戏 RNG 均不前进，恢复后的全部已测状态也相同。

替换 UV 改变 192,424 个实际像素：185,931 个此前不同的像素变为相同，另有一个此前相同的像素变为不同，11,693 个仍不同。Alpha 不因这次替换而改变；剩余 11,694 像素仍包括 9,545 个 Alpha 差异。原版捕获格式确为 A8R8G8B8（21），四个字节都保留比较，未删除 Alpha、FPS 或任何空间区域。

新病例的 counter 为原版 84／C++ 80，内嵌 VM 年龄为 85／81，差四次；旧病例差三次。两次结果分别保留，不将计数差归一化，也不依据像素数量选择一次启动当作通过。新病例中前四个私有 VM 仍全部 303 项一致，第五个仍只差上述六项，四个合成 VM 的 204 项已测字段仍一致。

此 GPU 控制建立的是两个 UV 字段对大范围画面差异的直接影响。它不是生产修复，不接受诊断反事实为实际画面通过，也未证明剩余像素全部由加载粒子、FPS 或某个渲染函数产生。下一步继续核对真实加载／Control 交接及剩余绘制来源，不能添加固定三／四帧、RNG 填充或捕获就绪表。

本轮没有新增原版 OS 游戏进程或复制游戏资产。真实 C++ Application、工作线程、两个宿主、GPU 和时钟均已收回，测试保持静音。首次实际画面、动画 RNG、相机缓存、所有模式与完整流程等原有门槛继续开放，`completeGame=false`。
