# TH14 GameSession 模式标志传递 · 2026-10-27

修正实际 GameSession 向 ECL 动画环境传递的模式标志。自动演示的录像头带练习属性，旧调用因此传入 `0x10`，遗漏原版的演示位；普通回放则传入 `0`，遗漏回放位。现在演示传 `0x40`，普通回放传 `0x02`，普通练习／符卡练习保留各自模式位。

此修改修复状态传递，尚未证明可见像素改变，也不归因 KMK 二面提前结束。原版普通界面、完整图像和浏览器仍未验收。

## 原版证据

已有独立原版进程的首次 Player 记录，在其声明的暖启动位清除之前，实际读到 `0x40`。该原始采集使用完整咲夜 B Hard 录像替换一个演示档案项；之后才清除演示位。这里只使用未触碰的首次标志读数，不将其后暖启动游戏称为普通回放。

另用[原指令控制](../../tools/th14-attract-run-flags-native-oct27.py)执行 ECL 554 的实际调用 `425577 → 434e10`。四种声明的 runtime mode、七组 flag 共 28 例，分别停在原版的跳过尾部或创建体之前。runtime mode 为 8 或演示位 `0x40` 已置时跳过；其他输入进入创建体。未替换原指令，未执行整条动画生命周期或原版游戏进程。

## 实际 C++ 调用方

只重编当前生产 `GameSession.cpp`，140 个经哈希核对的既有核心对象继续复用。实际 Application 通过只读夹具记录第一次战斗激活时的公开状态；另以链接包装器记录真实 ECL 554 调用，原函数保持原样。

| 实际入口 | 修改前 | 修改后 | 实际运行范围 |
| --- | ---: | ---: | --- |
| 自动演示，录像头仍标练习 | `0x10` | `0x40` | 2,264 帧、7 项断言 |
| 普通菜单选择既有咲夜 B Hard 录像 | `0` | `0x02` | 722 帧、16 项断言 |

演示的 131 行状态日志、两幅完整画面及 1,508,352 帧静音 PCM sink 保持相同。普通回放前缀的 39 行日志、一幅画面及 374,784 帧静音 PCM sink 也相同。动作终态、输入文件与保存文件均相同。两条入口只使用正常归一化按键或零输入，没有修改生命、关卡、计数器或种子。

这些窗口未记录到实际 ECL 554 调用；另一个延长至 3,464 帧的旧调用观察也未记录到该调用。因此，原指令组件的守卫结果与调用方的标志修正分别记录，不能写成“已纠正演示中的关卡标题像素”。第一次诊断构建因生成夹具的字符串换行错误失败，原日志和原生成工具保留；修正生成方式后使用新目录构建。
