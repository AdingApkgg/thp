# TH14 近裁剪修正后的运行复核

2026-11-05：对 [GLES 近裁剪修正](TH14_PORTABLE_NEAR_CLIP_NOV05.md)另行完成兼容路径、WebGPU、混合语义记录、两个浏览器构建及实际 Application 六面流程复核。以下均绑定同一组正式渲染源码，不能据此接受整作 1:1。

## 图形组件

原有 85 组输入在三种路径分别比较完整缓冲：GLES 使用 `EXT_clip_control`、同一 ANGLE 宿主拒绝该可选扩展后的兼容路径、独立 wgpu-native D3D12。每种路径各比较 104,448,000 字节，全部相同。它们共享 85 组输入，不能记成 255 组不同场景；兼容路径模拟扩展不可用，不代表另一台物理 GPU 已验收。

WebGPU 源码未因本次 GLES 修正而更改。其测试在沙箱中创建设备前发生访问异常，单进程重试仍失败，保留错误记录；常规权限下同一离屏宿主的 85 组逐字节对照通过，未操作窗口、浏览器、输入或音频设备。

另重放留存的一个完整混合绘制记录：192 个语义批次、416 次原生绘制、7 次清除，199 个检查点摘要与独立 D3D9 HAL 对照相同，最终 1,228,800 字节缓冲逐字节相同。输入包含从较早 C++ Application GPU 观察到的初始颜色，参考是这些语义指令的 HAL 重放；它不是原版游戏整局 framebuffer。

## 实际 Application

五个 Application／设备／渲染适配单元重新编译，141 个玩法对象与上一 Application 构建逐一验哈希后复用。新 Wasm `656574e8bf823b223ee1bbdadba1647eb11d996059f4b03fb84eb51ea6574937` 实际运行 122,780 帧，53 项断言通过：从冷菜单选择完整灵梦 B Normal 录像，走过六面，第 122,562 帧自然结束，稳定等待后返回列表／主菜单，执行 Quit 和生产保存。

与绑定同核心的旧 C++ Application 参考相比，15 份所选载荷、10 幅完整图像／12,288,000 字节、959 行各 303 字 VM及登记顺序、90,086,400 帧静音 PCM 摘要相同。新保存文件重新读取并校验摘要，输入录像 110,022 字节不变；物理音频设备打开数为零。这里只比较静音离线 PCM 摘要，未留存并独立重算原版整局 PCM，也未把旧 C++ 图像当作原版游戏图像。

## 浏览器目标构建

GLES 与 WebGPU 两个配置各全量编译 146 个单元，均没有复用 C++ 对象，四个渲染文件与正式源码逐一验哈希。两者的 Wasm 分别为 `0a9750bfe24129ec6005b197fe599b49c2adb62652e175c85e8c0b479f616794`、`340aad1aeac70cda36f084a3bf567cc2f31924feb10e9e09feafd875d0d0049b`。GLES 使用普通 SDL 回调，未据编译接受其 worker 回调序列化；WebGPU 使用既有后台解码和序列化配置。编译均不包含原版资产，未改受保护的根目录 ResourceCrypt。

首轮浏览器构建误把新 Renderer.cpp 与核心快照里的旧渲染头文件组合，编译失败并保留；修正构建器，使四个渲染文件明确取自正式源码，其余游戏源码／头文件继续冻结，再重新全量编译两个配置。这里没有当前浏览器启动、呈现、IndexedDB 刷新或真实设备验收，也没有自动部署本地二进制。
