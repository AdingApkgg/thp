# TH14 首次自机资源后台解析

2026-10-29。TH14 选择机体、启动演示、进入录像或再次播放时，自机 ANM 的实际归档解压和 CPU 解析现进入独立 worker。原来 `select_player` 在调用者中同步完成该项；现在先记录待交付的机体所有者，成功交付后才排入 file 9 上传。GPU／模板准备完成并恢复原上传控制器后，再创建自机、读取场景／HUD／ECL。未加入固定帧补偿。

取消会清除待交付所有者；不匹配、已取消、被替换及重复交付均在复制之前失败。实际浏览器的 worker 拒绝会成为 C++ 明确错误，不回退到主线程解析。关闭延期功能的消费者仍同步加载。

## 已验证范围

- 六个自机资源 `pl00`／`pl00b`／`pl01`／`pl01b`／`pl02`／`pl02b` 的实际生产 C++ 对象与独立 worker 数据包，在所有解析字段、浮点位及字节上相同。11 次有效交付、一次损坏交付、六种同步消费者，以及取消／替换／错误所有者／重复交付／失败批次控制通过。该组件没有 Application、图形或音频设备。
- 因资源类头文件改变，旧对象复用被构建器拒绝；失败目录保留。最终浏览器完整重编 146 单元。主 Wasm 2,744,745 字节，SHA-256 `dfebae6d7922c85ddff3c722a8c2a189cc81256fff31029a9f017f1f048e0160`。worker 文件与前次冷启动构建逐字相同，worker Wasm 76,918 字节。使用冻结源码中的正确 ResourceCrypt，未覆盖或发布根目录另一份无关修改。
- 从同一不可变浏览器源码新编译 141 个原生核心单元，分别链接实际 Application／设备／GLES 或 WebGPU。两后端各 2,264 帧、七项断言通过；状态记录、两幅完整 BGRA、339 个活动 VM、文件、RNG 与 1,508,352 帧静音 PCM 相同。实际队列观察到自机 CPU 任务尚未上传，随后 file 9 上传完成才出现 Player。
- 对待执行的自机解析、关卡解析、上传恢复分别调用实际生产暂停／恢复方法。旧回调返回后待执行状态不变。每例显式跳过五个宿主帧，仍执行 2,264 个 Application tick；七项断言、终态、完整画面、活动 VM、文件、静音 PCM 相同。按相同 Application tick 配对的采样分别为 124／123／124 组；未把相同宿主帧号下的不同游戏时刻比较为相同。
- 139 路由／27 项 HTTP 与实际服务主模块及 worker 字节核对通过。Chromium 156 静音页面观察标题、演示及 Normal 灵梦 A 717 帧片段自然结束／返回列表，所选 HUD 为 3100 分、1 残机、1.03 火力、2 Graze。
- 只在测试响应目录拒绝 `pl00.anm` 时，同一主 Wasm 实际报出 `TH14 background player resource decode failed`。故障服务已停止，正常 worker 恢复并重载；实际咲夜 B Hard 四面启动、暂停、“再次播放”重新加载四面及返回回放列表通过。

## 尚未关闭

原生宿主关闭浏览器 archive-worker 特性，提供声明的回调时钟；独立 CPU worker 协议由另一组件和实际浏览器验证。五帧暂停是明确的组件控制，不能作为物理浏览器暂停或原版线程耗时验收。

最早 sig／ascii／text、其余核心准备和后续换关尚未全部后台化；原版独立线程交付时序仍未严格复现。该构建没有重新验收旧 `7d49003` 的整段咲夜 B Hard 浏览器回放，亦不继承其结果。全模式、原版普通全流程、全帧图像与音频仍继续，`completeGame=false`、`nativeEquivalent=false`。
