# TH14 独立交付的完整会话对照（2026-11-05）

本次把上一轮的跨关恢复通道放入实际 GameSession，运行同一份灵梦 B Normal 六关录像。141 个玩法编译单元从冻结的 GLES 候选源码全部重新编译为 WASI；没有复用旧虚函数布局的对象。运行器执行真实解析、更新、CPU 动画绘制、资源分块转换和 FrameCadence，使用实际单调时钟与独立 Worker，不向引擎传入原版逐帧状态、种子结果或选定 VM／回调完成目标。

这是独立运行的集成实验。记录设备接收绘制提交，但没有执行真实 GPU 或音频设备；它也没有经过普通浏览器的冷启动。完整模式、原版时序和整作 1:1 均未验收，严格模式通过数不增加。

## 六关控制与实际交付

直接进入回放的对照运行自然结束，共 122,005 次 Player 回调，约 33 分 53 秒，实际经过一至六面。五个 incoming 资源 owner 都在结束前完成三次 RNG 存储和第四次录像全局复制；五个 Worker 均在清理前达到 ready／acknowledged 4、终结状态 2，随后全部退出。没有宿主错误或未支持弹幕操作导致的中止。

逐物理回调比较仍失败。直接入口跳过了启动加载的 RNG 消耗，第一次回调就有脚本 RNG 两字段不同。原始比较保留全部状态、75 项相机和 2 项 HUD 的差异，不能把进程正常结束当成原版一致。

额外使用同一录像的既有六关原版记录进行唯一「关卡、控制帧」配对，控制运行有 120,866 对；32 项状态中仍有脚本 RNG 两字段和活动弹计数不同，弹数共 110 处，相机有 21 个字段存在差异，所选两项 HUD 无差异。重复的加载／慢速帧键明确排除并列出。这个配对只用于定位差异，不替换逐回调门槛，也没有修改引擎状态或调度。

自然回放结束时，最后阶段的输入游标为 26,089，声明帧数为 26,469；两者相差 380。没有据此宣称读取到整个输入文件的 EOF。

## 真实加载消费者与保留的另一原版反例

单纯执行标题待机与 attract 入口并不能补齐启动差异。新入口执行冻结 SDL 的真实 `draw_startup_loading()`、签名和加载 ANM、每次一个 TextureImage 分块、源码定义的签名 180 次绘制门槛，然后通过真实标题待机进入 attract。原始启动 tick、安全 cookie 和声明几何帧只在初始化时提供一次；attract 标志按原版用例约定清除一次。没有预设 RNG 种子／计数，也没有补固定次数的随机调用。

在主参考记录的启动输入下，首回调的 32 字状态一致。随后实际 60 Hz 完整运行的原始复核确认：前 **14,067 次回调的全部 109 字**（32 状态、75 相机、2 HUD）一致；第 14,068 次、二面加载期间首次出现脚本种子和游戏随机调用数的差异。该入口的完整终结、五次交付和全部比较数据单独记录在[公开元数据](th14-independent-full-session-nov05.json)，不把前缀一致扩大为整局一致。

相同 Wasm 对另一份既有完整原版记录的启动输入仍有脚本 RNG 两字段不同：模型入口调用数为 1,360，另一原版为 1,336。反例使用当前哈希绑定 checker 再现并保留；没有为了匹配它增加常量偏移。这条加载前奏按 CPU 速度执行，未恢复实际冷启动 worker／GPU 时序。

## 调试记录的等待限制

主参考原版在二、三面各声明调用 Sleep 60 ms。直接观察的调用至返回间隔约为 **2,181.00 ms／1,880.69 ms**，期间分别经过 49／25 次 Player 回调；记录明确标记包含调用边界的调试器暂停。这些数字不能当作普通未插桩 GUI 的 Sleep 耗时，也不能据此把新的独立通道硬延迟到某个旧回调。严格失败保留，独立调度的原版等价仍开放。

独立通道的逐步确认也有额外成本，尚未校准；主线程 C++ 仍负责真正的状态写入，Worker 只提供就绪／确认。因此，本次的完整生命周期与四步交付成立，不代表恢复了原版所有指令级并发交错。

本轮也复看了 [TH20 当前源码工程](https://github.com/Oracatt/Touhou20/tree/011aa029d1dac51578107bc98a0006bd750e453c)。其 README 与运行记录分别报告独立构建、实际跨关和未完成的整局逐帧验收；运行修复还强调按原版时机启用 Player／HUD 回调。这一做法用于约束本次会话与资源 owner 的验收范围，没有把其他作品的构建完成标志计为 TH14 的 1:1 证据。

## 可复核内容与后续

`tools/th14-build-independent-session-nov05.py` 构建全部玩法对象，`tools/th14-run-independent-session-nov05.mjs` 驱动实际会话；直接控制使用的旧 driver 单独保留为 `tools/th14-run-independent-session-direct-control-nov05.mjs`。`tools/th14-verify-independent-session-nov05.py` 重算所有原始字，`tools/th14-independent-session-boundaries-nov05.py` 定位首次差异和等待边界，`tools/th14-independent-session-stage-pairs-nov05.py` 只做唯一帧配对。`tools/th14-independent-full-session-evidence-nov05.py --check` 校验冻结源码、141 对象、Wasm、终结报告、原始比较、探针反例和公开元数据。

最初的两个零回调初始化失败分别为 Wasm instantiate 返回对象处理错误和 Archive 借用缓冲区过早释放，原目录保留。汇总 checker 初版误用边界报告的键名，其失败与源码也保留，修正的是元数据映射。没有更改玩法源码或原始轨迹来掩盖比较失败。新的运行数据留在专用目录，资源继续复用，不复制大资源或清理共享证据。
