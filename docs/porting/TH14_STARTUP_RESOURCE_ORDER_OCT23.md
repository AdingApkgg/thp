# TH14 启动资源顺序修正（2026-10-23）

原版启动资源线程先加载 `sig.anm`（槽 1），再加载 `ascii.anm`（槽 2）和
`text.anm`（槽 0）。本次将 C++ 的 ascii/text 模板准备顺序，以及 SDL 的这两份
资源上传顺序改为 ascii → text。改动仅适用于 TH14。

`sig.anm` 的完整启动流程仍待实现。此前私有检查中，4915812 字节的 sig 资源曾被
误标为 ascii；现已由原版字符串、对象名、归档条目和内嵌图片名交叉确认，更正标签。
这份 sig 数据的通过结果不能作为 ascii 已通过的依据。

本轮原码检查在同一 CPU、堆和原生设备上推进 sig、ascii、text、front 的资源上传。
text 的两张空白纹理及两个 640×480 渲染目标都调用真实 32 位 D3D9/D3DX 接口，
成功后由原版指令清除资源就绪字段。`thbgm.dat` 的存在性检查也实际执行只读打开和
关闭，没有打开音频设备。解压继续执行原版指令；完整结果、返回边界、字典、源数据、
非输出堆内容及其他原版数据分别核对，没有把主机解码结果写回游戏状态。

当前源码修正通过 9 组延迟加载检查（3 个时钟输入 × 3 个等待长度），以及自然标题
到 Demo 的 1921 帧旧移植基线对照；所采集的 VM 状态、创建记录和 RNG 一致。
独立 SDL 候选编译通过，导入／导出接口不变；WASI 检查使用 141 份重新编译的引擎
源码。与本次无关的本机 ResourceCrypt 修改没有纳入构建或发布。

原码检查的线程切换和主线程 FPU 仍为声明的测试条件，尚未执行完整绘制回调、普通
窗口循环、声音线程或完整原版游戏。因此这些组件检查不代表完整启动或整作 1:1。
sig 的创建／清理时机、后续资源次序和启动绘制仍需继续核对。

本次发布源码与验证摘要；候选 SDL 尚未完成浏览器验收。本机静音预览仍使用先前已
固定的 `0e1ba6d1…` 模块，不能继承为新候选已通过。

`completeGame=false`，`nativeEquivalent=false`。只推进 TH14。
