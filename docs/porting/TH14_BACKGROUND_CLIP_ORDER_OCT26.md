# TH14 背景首差与半像素偏移次序 · 2026-10-26

当前生产渲染器保持原样；实际浏览器的 21 幅记录场景仍为 20 幅全缓冲一致，三面 1199 帧 `(144,373)` 蓝色 119／120 的严格失败继续保留。本轮得到可重复触发该差异的离屏重建，不将其标为发布版修复。

逐层原版 D3D9 HAL 实验将叠加前目标像素定位到背景第 3 个绘制调用。该四边形跨越眼平面和近裁剪面。取实际浏览器留存的 ANGLE INITIAL HLSL，保留其中运算并显式补齐输入／输出、常量缓冲和坐标连接，在独立 D3D11 设备重建同一绘制；普通与实例分支得到相同结果。保存的 Windows HLSL 文件换行为 CRLF，检查器还原 LF 后逐字节核对浏览器源文本哈希；这些文本不包含最终浏览器链接后 DXBC。

第二行的 UV、雾因子及 RGBA32F 源颜色与独立原版分组件结果逐字相同。两个 U 相差两个 binary32 最小单位，恰好位于本例过滤取整边界两侧。固定同一 UV 时，D3D11 两种纹理格式的采样／调制四项与原版一致；改用第一行 UV 的四个负控制保留差异。原版固定功能与显式 D3D9 vs2 `m4x4` 的目标 UV 相同；另用四个常量顶点比较 D3D9 vs2 和 D3D11 dot4，16 个裁剪坐标字一致。这些组件结果把下一步集中到裁剪与视口偏移的次序。

本次 D3D11 控制使用浮点视口原点。微软文档说明 [D3D11 支持小数视口](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/ns-d3d11-d3d11_viewport)，而 [WebGL 常规 viewport 的 x/y 参数为 GLint](https://registry.khronos.org/webgl/specs/1.0.3/)。因此该控制不能直接写成生产 WebGL 的 `.5` 视口设置。后续须验证适用于 WebGL 的通用裁剪／插值路径，并复验完整缓冲、其他 UV 场景和玩法；不采用坐标补丁、容差或把原版采样值输入游戏运行时。
