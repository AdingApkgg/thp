# TH14 Runtime 启动失败原因的保留

更新：2026-10-30。仅修正 TH14 Launcher 的错误处理；C++ 玩法和 Wasm 未变，整作 1:1 未完成。

## 实际问题

首次安装游戏包后，`ensureRuntime` 仍在同一个 `try` 内等待 Runtime 就绪。若这个阶段失败，原代码会显示回退提示，然后到达 TH14 不支持的旧资源入口，最终用“辉针城需要已安装的本地游戏包”覆盖真正的安装／Runtime 错误。此时游戏包可能已经成功提交，准备进度也可能残留。

实际新候选包首次打开曾停在“正在准备本地 Runtime”，随后出现该通用报错。该失败保留；具体原因尚未证明，不能称为已解决首次加载失败。重载同一已安装包后，临时事件观察层实际观察到 Runtime `ready`、`first-frame`、后续帧／音频健康消息及标题画面；它只观察加载和错误事件，没有替换任何游戏／Runtime 回调。随后已撤除观察层，保持静音。

## 修正与验证

生产 `app.mts` 现在在 TH14 进入这条失败分支时关闭准备进度，直接抛出原始错误对象，不再尝试没有实现的旧资源入口。取消逻辑保持原顺序，其他作品继续原流程。

[实际函数控制](../../tools/th14-runtime-startup-error-oct30.mjs)提取生产 `ensureRuntime`，用 Node 自带的 TypeScript 类型擦除后实际执行。12 项声明的 Package／Runtime I/O 控制覆盖首次下载失败、提交后的 Runtime 超时／设备失败、取消、无 Host、成功、已有包失败及 TH10 的旧回退控制。对照已发布旧源有 3 项错误被覆盖；修正后为零，原错误对象身份保持。两种成功、已有包失败及非 TH14 控制不变。它不启动浏览器、不修改存档，也不是实际浏览器故障注入验收。

[本机预览准备工具](../../tools/th14-runtime-startup-preview-oct30.mjs)先核对冻结 Launcher 的原函数与已发布源一致，仅将该函数替换为修正源的类型擦除结果，其余文件、C++ Wasm 和原资源不变。服务实际返回的字节也核对。新候选 Wasm 为 `da8e1bf5a2ae674df9c6299a2feeacd5029f0148ecf4d6b57e129e03d0be842a`，来自上一批首次 Replay 修复：2 个单元重编、144 个经验证对象复用；本次没有再次编译或继承整局通过。

[证明元数据](th14-runtime-startup-error-oct30.json)仅含版本、计数和哈希。原版资源、录像、像素、内存与二进制不发布。约 415 MB 生成字体／音乐仍通过既有不可变文件的硬链接复用，没有重新复制。

此前普通魔理沙 B Normal 的 27,251 帧二面失败保持；原版普通 GUI、完整浏览器流程／刷新持久化、60 帧稳定运行、全模式及完整像素／PCM 等价继续未完成。实际浏览器中当前还观察到约 1 Hz 的父／子 RAF 和约 4 次每秒玩法更新，原因没有唯一归因；诊断旁边的毫秒值是观测年龄，不能直接称为帧成本。30／25 清单不变，不作为整体 1:1 百分比。
