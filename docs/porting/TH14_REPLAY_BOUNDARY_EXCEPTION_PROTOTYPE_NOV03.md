# TH14 录像输入证据绑定与异常类型诊断候选（2026-11-03）

新增[输入边界复核器](../../tools/th14-replay-observed-input-boundaries-nov03.py)，将原版观察到的终止标记或关卡录入帧数用尽，分别与原始录像、原版解码／独立镜像的结果、声明帧数和原版报告绑定。没有安装观察器或没有命中时记为未知；即使观察到最后一关输入用尽，也不将其等同于文件字节 EOF、游戏通关或整作 1:1。一个合成用尽正例、四个篡改反例、无观察器控制及扩展观察器绑定控制均通过，见[复核摘要](th14-observed-input-boundaries-check-nov03.json)；这些事件均为合成，不是原版现场。

此前两份采集出现的首次机会异常码 `0xe06d7363` 是 Visual C++ 使用的 C++ 异常码；异常被调试器首次看到并不自动表示程序崩溃。微软说明此类异常参数的类型布局属于[用于调试的实现细节](https://devblogs.microsoft.com/oldnewthing/20100730-00/?p=13273)，不能仅凭异常码判断具体来源或影响。

因此新[观察器候选](../../tools/th14-native-terminal-exception-observer-nov03.py)在原有只读录像边界观察之外，针对 32 位参数尝试有界读取异常类型描述、所属映射模块及停止线程上下文；遇到不支持或不可读数据时保留失败信息。它不添加游戏写入或显式线程挂起，不删除异常，也不允许未解释的异常通过严格门槛。类型读取的一组正例和六组反例、原边界处理及寄存器配置未变的检查均通过，见[合成组件报告](th14-exception-type-capture-unit-nov03.json)。目前没有真实异常类型命中，原因仍未知；长录像前先运行静音短前缀，失败时保留原观察器。
