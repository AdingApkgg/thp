# TH14 普通主循环二面加载核验 · 2026-10-15

本轮把原版资源线程首次 `Sleep(60)` 期间的普通主循环接回，再让主循环自己调用资源泵。原始等待期间执行了 3 个 Player 回调，声明的主时钟前进 66,666,600ns；随后原码在 `45610f / 456129` 初始化 gameplay RNG。没有修改 RNG、补调用数或代写加载完成标志。

随后依次处理 logo 2 块、背景 6 块、通用敌人 3 块、二面敌人 16 块，共 27 块。所有资源 helper 都由原版普通主循环的 `47d799` 调用，没有从宿主显式调用 helper。普通主循环还消费了音乐队列；原码资源回调成功返回，CRT 清空自己的 FLS、释放 PTD 后请求 `ExitThread(0)`，该 API 未执行。独立解码比较的资源、消息、场景及 ECL 文件共 7,507,280 字节，差异为零。

用完整公开咲夜 A Normal 录像及当前 267 个核心源码／141 个对象，重跑到第 9,703 个 Player 入口。原版前缀 9,669 行与原记录逐字节相同，本轮普通主循环后缀 34 行，包含初始等待期间的 3 行。

27 个资源块的顺序、文件槽、块编号及完成于哪个 Player 回调边界，均与原码记录一致。原版新敌人管理器首次在索引 9,680 的 Player 入口存在。此前单独运行 worker、让 main 在初始 60ms 等待期间暂停的分支少执行了这些回调；不能据那条分支调整生产计数或时钟。
