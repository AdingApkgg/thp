## 当前工作的瓶颈

1. 原版实际进程捕获走吸引演示，3900 帧退出限制了长回归。分关窗口无法替代完整换关与整局。
2. GPU 独立候选过多。在完整原版回放基准未建立时，反复缩小少量像素差异占用了主线时间。
3. 普通输入控制器调参有助于取得自然录像，但这是测试素材生产，不等于移植核心的进度。
4. 现有大量单元证明不能自动相加成为整作等价；每次核心修改仍需要完整基准回归。

## 执行顺序与约束

第一优先建立 TH14 原版完整回放执行和不可覆盖的基准。先利用已验证的原版入口和真实进程初始化快照，列出每个宿主边界；原版游戏代码继续执行。未支持的调用必须停止并报告，禁止通用返回成功、修复栈或用候选结果补齐。只读快照启动本身不算整局通过。

随后建立快速原始 Demo 检查和长 Normal 六关检查，再扩大到六自机、难度与 Extra。只接受真实终止和有序换关；崩溃、预算耗尽或只捕获前缀统一标 INCOMPLETE。不能裁剪、重新同步、改 RNG 或让候选生成原版基准。

玩法完整回归稳定后，继续严格图像、音频、菜单、成绩及浏览器持久化验收。失败的 GPU 候选保留来源和数据，不进入生产渲染器，不把误差很小描述成像素一致。

先前核心的 Easy/Normal 咲夜 A 自然通关和移植内部完整录像回归已有通过记录；这些证据绑定各自版本，不自动继承到后续改动。原版不间断整局、完整图像、音频及浏览器存储验收仍未完成。详情仍以 CORE_STATUS 与各报告的实际范围为准。

## 新方法的实际结果

原版执行后端现与独立原版进程核对到3,901帧：每帧15组、64个状态字，共249,664字全部相同，包含玩法与视觉两个RNG。没有字段掩码、重新同步或库存/血量修改。通过版本固定在 `tools/th14-native-backend-reference-oct13.py`，独立检查报告为 `th14-native-backend-3901-verified-oct13.json`；后续实验在另一份提供器中进行，不能继承这个通过结论。

当前生产移植核心对同一基准的30个玩法字段无差异，7,802个启动视觉RNG字差异仍保留。原版后端会严格处理返回标题的请求，因此这3,901帧仍是吸引演示前缀，不是第一面通关或完整普通录像。

普通保存录像模式正在补齐启动与宿主服务。现有试验在暖启动快照执行原版的模式清理指令，显式记一处模式初始化；尚未覆盖真实菜单与加载器的完整启动链。符卡字体使用实际GDI栅格化，BGM读取只使用原始容器的只读字节，图形上传与静音设备服务均不作为图像/音频通过证据。每个未知接口保留失败收据后补齐明确协议，下一步仍是完整第一面与有序换关。

长基准已发现并修正一个生产缺陷：原版 MSG 构造函数 `4320b1..4320c4` 和 ECL 518 各做一次弹幕/激光/敌人清理，移植曾只保留后者。空掉落也调用 RNG，两次清理不能合并。第5,522帧原先少4次玩法RNG调用，并最终在原版第8,618帧GameOver；修正后8,618帧的30个玩法字段及捕获对象窗口无差异，启动视觉RNG差异仍保留。独立原版进程与执行后端的551,552个状态字一致，报告为 `th14-warm-replay-8618-constructor-clear-verified-oct13.json`。两份未改原始演示也各重跑3,901帧通过。

旧录像在原版不能自然通关，不能以移植自身的回放一致性当作原版整局证明。对话修正后的三条新普通输入路线都在五面GameOver，未计通过；下一步引入可追溯的真实原版长录像并继续固定基准回归，避免把主要时间用在自动控制器调参。
