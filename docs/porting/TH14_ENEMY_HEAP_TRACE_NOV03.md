# TH14 原版敌人分配短窗口

后续静态核对发现，这次使用的释放断点 `0x4854fe` 只是跳往 `0x4855d2` 的入口之一，而原版也有直接调用 `0x4855d2` 的指令。因此，本次记录可能遗漏对象释放；下述模型比较仅针对记录到的部分事件，不能视为完整生命周期或完整堆历史。

在单独的原版进程中，使用声明的 Replay 暖启动和主线程硬件断点，先完成 600 回调预检，再完成 3,000 回调诊断；两次音乐与音效主音量均实测为零，均无报告调试异常。观察窗口只覆盖首次 Player 回调之后、发布跟踪结束后的第一面主线程。原版指令、随机数、计数及输入未修改；预先声明的首次回调仅清除 attract 标志。

3,000 回调记录到 81 次敌人工厂分配返回、80 次属于已观察对象的 CRT 释放入口，56 次分配重用了窗口内之前观察过的地址。另有 24 次 CRT 释放入口不属于窗口内已观察敌人，未在这项跟踪中归因。释放入口不是释放成功证明；窗口之前、其他线程及其他堆分配也没有覆盖。[原版事件摘要](th14-enemy-heap-trace-nov03.json)不包含地址或原始事件。

把观察到的对象生命周期转换成合成对象编号后，隔离堆候选对 81 次分配中的 42 次重用身份预测一致；以首个分配为基准，仅 1 次相对位置一致。模型只接收声明的分配大小和已观察生命周期顺序，使用合成地址；实际原版地址只在校验端用于比较。这个诊断假设观察到的释放入口随后成功，且没有模拟未观察到的其他分配。[对照摘要](th14-enemy-heap-model-trace-nov03.json)保留该限制。

结果说明当前同尺寸候选不能重建这一原版进程的堆历史；不能据此修改生产分配或关闭 `worldZ` 字差。完整模式、普通菜单、原版整局图像／PCM 和整作 1:1 仍未验收。
