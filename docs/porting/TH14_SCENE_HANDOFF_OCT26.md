# TH14 场景相机交付与保留差异 · 2026-10-26

灵梦 A Hard 的相机差异来自对照夹具漏掉的线程交付窗口。原版主线程开始下一次资源更新后，Scene 工作线程在控制器发布相机之前复制了上一帧绘制留下的相机。此前夹具只处理标为 draw 的复制事件，因而错过这次复制。生产相机公式、玩法、渲染和音频均未修改。

对照工具现在根据实际原指令边界和时间戳，在上一帧 draw 之后交付 Scene，再从实际观察到的下一次控制器相机发布边界继续更新。它检查连续 Player 回调、线程、关卡、原指令地址和时间顺序，不把原版相机数值传给引擎。缺失该边界时直接失败，不猜测完成时间。

灵梦 A Hard 相机 25 字在完整记录中全部一致。历史完整基线有 18,399 回调的 right.x 字差，但使用较早玩法 Wasm，不能称为同构建完整 A/B。另一个严格同诊断 Wasm、同原版输入的 56,000 回调 A/B 中，仅改变宿主调度便使 933 个相机字差变为零；两边动画失败均保留。

灵梦 A Lunatic 的原版记录已稳定观察到结束菜单，进入一至六面，清单新增这一组自然结束和全部关卡入口记录。结束菜单与入口覆盖不证明六面通关。该记录的五个动画字差使默认完整复算工具继续拒绝生成通过报告；Hard 的六个字差同样如此。

另一个[336 组受控原指令实验](th14-shot-hit-stack-z-component-oct26.json)确认：`452050` 命中回调中的极坐标辅助函数只写局部 X/Y；`4520f2` 读取尚未写过的栈 Z，`4520f7` 才写回，然后作为 effect149 的工厂参数。声明自机弹 Z 为零，改变七种有限的合成栈输入，在四种年龄、两种火力、三种种子及两种半径的组合中，只有工厂 Z 改变，所测 X/Y、角度、伤害、RNG、计数及服务参数保持一致。实验控制了分配、声音和中断服务的返回边界；没有观察实际运行中的栈来源，也未执行特效工厂、子对象和后续生命周期。因此不会据此删除、归零或放宽完整记录的 Z 字比较。

[独立复算报告](th14-scene-handoff-verified-oct26.json)重读原始状态、相机、HUD、动画及压缩战斗对象，保留失败数量；通过回归另由默认[严格完整工具](../../tools/th14-verify-native-campaign.py)复算。仅发布范围、哈希和计数。原始资产、录像、内存与二进制不发布。
