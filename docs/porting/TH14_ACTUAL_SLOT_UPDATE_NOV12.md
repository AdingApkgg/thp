# TH14 灵梦 B 实测槽输入的完整单弹更新对照

六处具有原版前后弹池快照的活跃弹数量分歧，现在已对照到完整单弹更新函数，而非只对照 quad 几何。对同一份实测输入执行原版 `4510b0`，再仅将 VM 的旋转 Z 替换为相同输入坐标下保留的 C++ 角度，会切换保留／退役分支；切换结果与各侧下一输入时刻的槽状态一致。恢复原角度则重现完整组件基线。

| 关卡／输入游标 | slot | 保留原版角度后的 state | 替换为 C++ 角度后的 state |
| --- | --- | --- | --- |
| 2／2143 | 201 | 2 | 0 |
| 2／5514 | 228 | 0 | 2 |
| 2／6285 | 189 | 0 | 2 |
| 2／6286 | 210 | 0 | 2 |
| 2／6291 | 159 | 0 | 2 |
| 3／1478 | 216 | 2 | 0 |

原版组件使用已保留的 208 字节 slot、1484 字节 VM、64 字节 SHT spec 和 36 字节渲染全局数据。没有按模型重造这些原始记录。运行完整的运动、quad、可见性判断、退役分支和保留后的 Timer 更新，记录 `45124e`、`451288`、`451290`、`45129f` 的实际组件执行路径。读取门槛拒绝未声明的现场数据依赖，写入限于克隆槽、克隆 VM 和组件栈。

时钟速率 0／0.5／1／1.5／2 为声明输入，并非声称已从旧原版快照采集该值。每种速率执行原角度、替换角度和恢复角度，共 90 次原版单弹更新。30 组旋转替换均切换分支，30 次恢复均逐项重现组件结果，替换后的全部 12 个 quad 字与保留的 C++ 几何相同。

ANM lookup 返回已捕获的原始 VM，release 记录调用并清除句柄，cookie 校验使用声明值；三处服务入口为组件边界，未执行真实池析构。另声明 CRT SSE2 分派标志为 1、MXCSR 为 `1f80`、x87 控制字为 `037f`，不把这些环境值冒充现场捕获。原版图像的静态 anchor 表来自已校验的 EXE。

当前 C++ 对照使用 `e6b15d27` 游戏源码对应的 141 个已验证对象，新增夹具按正常 C++ 访问权限编译。原始快照中的更新依赖显式映射到公开字段，只执行真实 `ShotManager::update`，不执行动画脚本或改变 live Application。六个槽、两种角度、五种速率共 60 例，比较 quad、槽状态／句柄是否存在、Timer、位置、速度、VM 位置和旋转，全部 1680 个字相同。C++ 真实 release 标记另外检查，未与声明 release 服务混为原始 VM 身份相等。

新增输入门槛先后拒绝了渲染数据长度假设、未声明 CRT 标志、遗漏静态 anchor 表和遗漏嵌套 cookie 检查四项夹具问题；原始源码与失败记录均保留。这些不是游戏引擎比较失败，也没有通过修改生产代码来消除。

这将这六例的后续排查集中到角度产生前的 RNG 相位和恢复／加载交错。先前已定位 `pl00.anm` 脚本 6 的随机引用，但完整调度和唯一分歧生产者仍未证明。第七处没有原版池数据的反例保持缺失，旧严格录像失败、首 Present 的 24 次 SCRIPT 差异、图像、音频和其余模式验收均未关闭。本轮没有改动或重新部署生产游戏代码，也没有启动原版 OS 游戏、GPU、声音设备或重跑长录像。

本地重查需要保留的原版／C++ 采集包、原版 EXE、WASI SDK 和 Python Unicorn；这些原始快照及游戏资产不进入公开仓库：
