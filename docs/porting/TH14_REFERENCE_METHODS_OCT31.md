当前 TH14 继续采用可复用的源码对象与受影响模块重编，复用原版资产而不复制大包；原函数隔离对照只服务验证，不进入生产运行时。新时序样本结束后自动执行当前核心严格比较，保留失败，避免每个阶段都需要手动启动下一步。

本轮具体推进的是既有魔理沙 A Easy 随机数缺口：原版捕获扩展至声明的 48,000 回调，继续读取 worker 与正常 VM 调用顺序；保持 1,800 秒、128 MiB 观察数据及至少 100 GiB 磁盘余量。后续比较不注入推定的正常动画入口时间，也不传入原版 RNG、VM 或句柄作为游戏运算值。它与此前 33,000 回调时钟投影分别保存，尚在运行的样本不记通过。

生产 `GameSession` 在正常动画入口经 `stage_load_clock()` 读取时钟，正式 `Application` 使用 `SDL_GetTicksNS()`；暖启动夹具则固定输入时钟。已有短样本表明更细的交付时点会改变恢复相对于 NORMAL／OVERLAY 更新的位置。因此先检查实际交付顺序，不能据夹具时钟粒度直接增补固定随机数次数或固定帧延迟。
