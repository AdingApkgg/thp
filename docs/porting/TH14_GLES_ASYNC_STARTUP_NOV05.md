# TH14 GLES 异步帧循环修复（2026-11-05）

普通 WebGL2 候选此前黑屏停在 `text.anm`：页面可见、音频上下文运行，JS RAF 持续，但游戏 RAF 只调用两次。第二次 C++ 回调最终返回 1，原始 RAF 包装器却在 Asyncify 展开时先读到 0，因而不再请求下一帧。该旧失败保留在本地证据目录。

本机 SDK 的 SDL 3.4.2 `Emscripten_GLES_SwapWindow` 在启用 Asyncify 时调用 `emscripten_sleep(0)`；SDK 的 `emscripten_request_animation_frame_loop` 直接读取间接调用返回值。这与实际诊断的提前返回相符。

修复让 TH14 GLES 帧和加载工作通过具名导出及 `ccall({async:true})` 完成；只有等待 C++ 恢复并真正返回后才请求下一帧。输入及其他 Launcher 修改排在同一队列，避免在挂起的 Wasm 栈中重入。停止返回值仍生效，异常停止调度并报告。WebGPU 与其他标题保留原有分支，GLES 未改成 WebGPU。SDL 渲染和混音逻辑未绕过。

`th14-build-async-gles-nov05.py` 重新编译 Application；逐一核验并复用其余 145 个对象，其中玩法对象 141 个。新增回调头文件只由 Application 包含。首次构建因 EM_JS 不接受内联函数指针声明而链接失败；改用类型别名后重建成功，失败日志保留。成功 Wasm SHA-256：`4a8e02cc5d27c6fe13c3948fe750f9050d2a941421056a3f5b12bf745eedeca9`。
