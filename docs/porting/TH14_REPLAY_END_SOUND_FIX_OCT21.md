# TH14 回放结束与暂停调度修正 · 2026-10-21

本轮只推进 TH14，整作 1:1 尚未完成。修正针对实际流程：Replay 自然 GameOver 原先直接返回标题；暂停动画先后顺序、恢复／续关所在物理帧，以及正在播放的音效也存在差异。

原版 Player 在 priority 18 内调用 `448ef0`，先以旧动画速率创建 text52 和 front131，再切到暂停速率 1。菜单等待后只开放返回标题和重新播放，入口本身没有 SFX14。移植现在在相同的 Player 回调边界进入该菜单，保留 Player 与本帧剩余战斗回调；没有增加 GameOver 后整帧提前返回。

原版回调按 overlay ANM 8、菜单 9、控制器 11、普通 ANM 29 排序。暂停位在控制器 11 终止本轮遍历；恢复／原地续关在菜单 9 清除暂停位，同一物理帧继续战斗。修正将暂停动画更新移至菜单逻辑之前，并使恢复／续关继续该帧的剩余更新，避免重跑 overlay。普通暂停和 GameOver 的初始 VM 也在旧速率下创建；续关先恢复旧速率，再刷新 HUD 和 option。

音效按原 `4373b0`／`449020` 保存 76 个声音的播放状态并停止，继续时从当前游标恢复，允许菜单在暂停期间复用声音。只清音效队列的首哨兵，保留原版残留队列行为。新槽计数按 `46e458` 设为 1，修正此前累加旧计数的问题。GameOver 音频按事件所在位置处理，先清此前队列，再处理菜单和后续战斗声音；强制 Replay 结束没有新增提示音。

原版实际进程已自然运行至第 89,235 次 Player 回调的 GameOver，并捕获后续 120 次菜单入口。菜单的 120×10 个对应字段全部相同；结束当帧与随后冻结的 3,600 个非视觉原始状态字相同。240 个视觉 RNG 字差完整保留，绝对调用计数相差 1,080；没有通过改种子或归一化抹去差异。原版观察仍使用明确记录的暖启动／吸引模式初始化，不能据此宣称普通冷启动完全等价。

普通 Pause/Resume 的 Escape 和确认两条路径均实跑：恢复所在物理 tick，战斗帧、自机计时器等推进一次，overlay 和普通 ANM 各执行一次。每条路径的 71×32 个回放状态字与不暂停对照相同。真实菜单 VM 的年龄也只推进一次。

另外实跑“恢复后同帧再次 GameOver”：事件按 PauseResume→GameOver→后续声音排序，即使帧前帧后都处于暂停，也不会漏掉中间恢复。普通零输入游戏自然在第 964 帧失败，经唯一一次确认在第 988 帧原地续关；战斗与自机各推进一次，恢复前经济状态和事件顺序均核对。TH12／13 的共享源码共十个编译单元回归通过；这不代表推进其他作品。
