# TH14 启动签名绘制与释放修正（2026-10-23）

TH14 冷启动现在读取真实 `sig.anm`，在第 60 绘制优先级首次创建 sig 脚本 0 和 ASCII 脚本 17。资源逐块上传完成且实际加载绘制计数达到 180 后，先退休 sig 动画，检查引用已经清空，再释放 GPU 与 CPU 资源，随后发送 ASCII interrupt 1 并允许标题推进。

此前只有 ASCII 加载动画，签名资源没有进入启动流程，上传结束便直接开启标题。此次只修改 TH14 的启动绘制回调和 SDL 生命周期。

依据本机 TH14 原始程序（SHA-256 `f08e885e28d2e0fc8c579e88034dd7de8f2a648d8f08ce781cf08eadc9ffe353`）的指令：`0x44478f` 增加加载绘制计数，`0x45959a` 与 180 比较，`0x4595e1` 卸载 sig 文件槽 1，`0x459607` 开启标题更新。这是原始字节静态核对；本轮没有宣称完整执行原版标题工作线程。

验证结果：

- 虚函数接口改变后完整重编 146 个 SDL 对象；最终 Application 修改重编 1 个对象，其余 145 个对象逐个核对首次全编的哈希。最终 Wasm：`fdfac6be22827fc29588be082b1e882aabd2ffdd6c7558e9bd25bfa2210048d8`。
- 9 组延迟核心加载检查通过。它们检查核心模板与加载时钟，不执行 SDL Application，也不单独证明签名的 180 次绘制。
- 独立本机静音地址 `http://localhost:8213/?game=th14` 使用普通运行版本，冷启动记录 115 次公共 ANM 块上传，签名在第 180 次绘制后释放；创建至释放日志间隔 3.049 秒。
- 实际观察到标题、自然 Normal Demo、普通菜单 Normal 灵梦 B 开局、一面自然 Game Over 及菜单返回标题；浏览器错误和警告均为 0。保存的截图覆盖标题、Game Over 和返回标题，没有将启动器准备画面标为签名动画截图。

仍未完成：sig/ascii/text 的初始 GPU 准备仍同步；原版异步线程、完整物理帧时序、像素等价和整作 1:1 尚未验收。原版 `0x180` 标志允许跳过最低等待，本次仅实现普通启动等待；冷加载期间强制 JavaScript 重启亦未验证。历史完整回放结果不自动计入本版 SDL 验收。
