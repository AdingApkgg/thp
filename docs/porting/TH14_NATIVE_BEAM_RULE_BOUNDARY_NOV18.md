# TH14 三面首次激光规则分歧的原版现场 · 2026-11-18

魔理沙 B Lunatic 样本的分歧已定位到三面 **第 2,157 帧**的一次激光回退。原版 Windows 进程的实际调用现场与移植对应调用的 **18 个输入字段全部相同**，其中栈临时值确实为 `0x7ffffffe`（NaN）。这次差异来自已声明的有限长度保护，不能归因于尚未知的擦弹半径或该调用的栈模型错误。

原版函数在这一输入上把 NaN 写入激光和碰撞区域长度；规则 1 保留此前有限长度 **294.589599609375**。计分／擦弹差异仍保留原值，本轮不改分数、擦弹、库存或 RNG，也不将查明原因记作整作完成。[逐项输入、哈希和范围](th14-native-beam-rule-boundary-nov18.json)。

## 相互衔接的证据

1. 复用旧未标记原版输入的规则 0／保护版观察流，最早特效 RNG 分歧在 2,171 帧，分数在 2,172 帧差 10，敌机数量在 2,180 帧不同；擦弹差异更晚出现，继续重复判定半径查询没有针对性。
2. 以当前公开核心和真实新自录 T14B1 文件制作只读观察夹具，仅采集第一段至 2,182 帧的 899 次激光调用，共 143,840 字节。与无观察器版本共同前 2,192 回调的全部 32 字状态相同；停止批次的额外 15 行原样保留，不截断原始文件。
3. 899 个实际调用输入送入原版 `452700` 指令，898 个的几何／命中计数／返回伤害完全相同；唯一不同项正是 2,157 帧的 NaN 传播与有限保护。ANM／cookie 服务及 hit-last-frame 是明确控制边界。
4. 同一 Wasm 下，仅把新录制尾部显式规则字段由 1 改为 0，作为私有合成对照；加密载荷／按键／关卡头未改，原始文件保持。观测到相同的 2,171／2,172／2,180 帧首次分歧。该文件只用于规则对照，不冒充原版或正常生成的录制。
5. 真实原版进程从完整输入自然推进，只在首个 Player 和目标激光现场两次命中硬件断点，之后在目标处诊断退出。实际栈值与参数再次吻合，排除了仅由提供给指令 Oracle 的假定栈值造成这一结论。

现场配对使用帧、激光计时、起点、角度、目标与形状的 11 字精确键，候选唯一；剩余七项输入（包括栈值）再独立核对。没有最近邻／最大匹配配对。原版可执行指令未改，RNG、分数、生命和输入没有写入；既有参考方法在首个 Player 清除一次吸引模式标志，实际输入通过私有归档的 demo0 提供，其余 226 项保持。此为声明的暖录像参考，不冒充通过普通原版 UI 选择录像。

## 结果的使用

保留既有两规则语义：无标记旧录像使用原版路径，普通游戏与新录制记录有限保护规则。原版激光使用未初始化临时值而可能令同一录像产生不同结果，亦见[原版缺陷分析](https://nylilsa.dev/bugs/th14/marisa-laser/)。本次把当前样本的实际现场与该代码路径对应起来，不把外部分析代替本地验证。

原先的额外一次擦弹及最终高 4,360 分没有被改写成原档案分数一致，四份原版提前结束输入也仍不称完整六关通过。后续按明确规则评估兼容性与可观察行为，不再将这个已确认的 NaN 保护分支当作未知碰撞数学问题反复重跑。

[可重跑指令 Oracle](../../tools/th14-oracle-beam-window-nov18.py)接收 `--capture`（含 40 字记录／报告的私有采集目录）与 `--output`。 [最小原版现场工具](../../tools/th14-native-beam-caller-window-nov18.py)接收 `--assets`、`--config` 和 `--output`，只使用已有不可变缓存、隐藏静音子进程与硬件断点；公共版只是将成功运行脚本的路径参数化，核心调试器正文逐字节相同。原始内存、录像、游戏资产及二进制均留在私有 artifacts。

两次原版观察器失败保留：首版漏识别 WOW64 单步事件，第二版混用新关号与旧帧号；最终版先确认三面计时已开始，再安装目标断点。游戏没有为这些观察器修正而改变。整作 active，实际用户入口的长距离定位误超时另行修复与验收。
