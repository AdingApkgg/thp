# TH14 灵梦 B Hard 六面记录与 REP 分段读取 · 2026-11-05

新原版记录完成六面共 107,243 次 Player 回调，零调试异常，观察到录像结束菜单。音乐、音效均为零；观察器只进行已声明的 attract 标记清除，没有 RNG、计数、生命或输入写入。完整录像保持不变，结束菜单不等于已观测输入 EOF 或通关。首次零回调启动超时单独保留，原因尚未证明。

在声明原版宿主时钟和资源完成事件的诊断运行下，当前 141 个玩法对象全部复用，未修改游戏核心。32 项状态逐字节一致；从第 2 个回调起，8,043,150 个相机字、四项录像游标一致，两项 HUD 字段一致。独立从本地原始载荷重算的 1,240 行／各 303 字 VM 及注册顺序、1,081 个战斗检查点（312 个非空）和启动窗口内 5,189 次发布身份均一致。公开[统计、路径与哈希](th14-hard-full-context-nov05.json)不包含原始载荷。

原比较器先后因两条原版前提不成立而中止，尚未执行模型。第一条把调试通知时的相机源快照当作 REP 已经读到的内容；第二条要求复制开始和稍后读取时的整个源相机相同。这两个要求不能用于并发原版读取：已经完成的前缀必须保留，而尚未读取的字段可以随后更新。准备失败的日志和旧对照输出均保留。

本次诊断明确区分以下两个窗口，使用原版指令位置、已完成读取前缀和写入代次进行分类，没有向引擎输入原版相机值：

两个窗口的私有读取前缀、最终 75 字快照和等待期间的私有资源所有权检查均通过。六面的归一化尾字控制允许 Y、Z 中实际发生变化的非空子集；原版 Z 为零时不强行要求 Z 改变。四面只校验已经完成的读取前缀，未把复制开始时的未读 Y／Z 固定为后续值。

同一 Wasm 的负例仅去掉上述两处时钟／读取等待，其余调度输入保持不变，重现 **473,540 个相机字差异**。失败日志和完整字段差异保留。正式诊断驱动会在前缀或完整快照不相同时失败，不以进程完成代替字段验收。

现有异常和 Initialize 门槛通过；Scene 门槛仍以 `Unreviewed Scene scheduler driver` 拒绝该诊断驱动，白名单没有修改，也没有增加原有严格模式通过数。**这些结果只验证受到原版观测约束的合法推导交错，未恢复原版精确指令交错或普通独立线程调度。** 读取代次分类确实使用原版观测值，不能声称完全独立的调度输入。
