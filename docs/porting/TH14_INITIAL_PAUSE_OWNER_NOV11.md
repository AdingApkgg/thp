# TH14 初次加载中的暂停菜单所有权

原版初次加载在 `435f22 → 448270` 创建暂停菜单，位置在 HUD、弹池、道具池及空激光管理器之后、ECL 初始化之前。`448070` 注册 Main9／Draw64，初始化两个计时器；恢复入口 `449020` 保留该对象。移植版此前在每次暂停时新建菜单、恢复时销毁。

TH14 初次加载工作线程现在创建私有的闲置菜单；主线程进入暂停或结果菜单时取得同一个对象，恢复后将其归还，结束会话时释放。后续关卡保留对象。每次开始暂停按原版 `448e1a` 清零禁用选项数量，保留数组内容，避免复用时残留上一轮禁用项。

验证范围：

- 原版完整执行激光、暂停菜单、分数弹字三个工厂、注册节点构造和真实注册插入；两组 RNG 状态不变，写入次数为零。激光复用已经缓存的 file7；分数弹字的 `259` 是精灵绑定，不是脚本执行。CRT 内存服务及日志为声明边界，精灵表为受控数据。
- 原版暂停入口前缀的八组禁用计数输入均清零计数并保留数组。冻结投递为声明服务，图形／音频暂停正文不在该前缀验证范围。
- 实际 C++ `GameSession`、暂停入口、ANM 模板与菜单更新执行四次暂停／自然恢复；输入中声明继续次数及录像状态。旧实现分配、销毁四次；新实现只分配一次，恢复时不销毁，结束会话时销毁一次。另检查首次激活前关闭、结果入口复用、错误线程及重复准备拒绝。构造不改变 RNG，没有打开音频设备。
- TH12、TH13、TH16 的九个实际翻译单元预处理结果与修改前相同。完整浏览器构建使用正常访问权限；组件新增的构造方法也在正常权限下单独编译。

首次组件夹具沿用的 `-fno-access-control` 放宽了访问权限，使一段直接读取弹池私有存储的冗余检查未被报错；正常浏览器编译发现此问题。检查已移除，实际生产调用位置仍在弹池／道具池初始化之后。早先的源码快照、失败日志和修正后的独立构建均保留。

RNG 与整帧图像对照继续保留为未通过项。初次对象寿命和菜单循环的组件通过不代表整作 1:1 完成。公开字段和具体构建范围见[结构化验证](th14-initial-pause-owner-nov11.json)。组件源码为 `tools/th14-initial-pause-owner-component-nov11.cpp`；准备好对应构建后可运行 `node tools/th14-run-initial-pause-owner-component-nov11.mjs`。
