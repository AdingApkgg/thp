# TH14 Normal 实际 RNG 读取与比较时钟诊断 · 2026-11-05

新灵梦 B Normal 原版观察完成 35,000 次 Player 回调，零调试异常，保留三面脚本 RNG 的 64 次实际访问，组成 32 对 `next32` 种子读取／写回。该记录按预定前缀主动结束，没有验收完整录像结束或 EOF。当前 C++ 核心在声明时钟及代表性帧入口的诊断中，64 个读取／写回值、对应回调和访问顺序、采样的调用计数字均与原版一致；35,000 回调的 32 项状态（含活动自机弹数）、从第 2 回调起的 2,624,925 个相机字、游标／HUD、774 行各 303 字 VM 和 373 个战斗检查点（49 个非空）独立复算一致。

这次直接检查指令实际读写的值，补充了此前只核对恢复后种子和计数的范围。原版在 `0x403336` 执行种子 XOR 后，停住的 AX 可以还原刚读入的种子；`0x403373` 写回后的 CX 保留实际写出值。全局内存快照可能已经属于后续写入代次，不能直接代替上述值。隔离原指令组件的 210 个受控用例全部恢复正确，其中 189 个后续全局快照不同；**本次实际原版的 64 个访问没有出现这种冲突**。本记录只覆盖 `next32` 的读取和写回，不据此接受 `next16` 解锁后的返回重读或整个 RNG 调用路径。

玩法核心没有修改，141 个对象逐哈希复用。新增 C++ fixture 只输出自己实际读取／写回的值，没有接收原版种子。该窗口输出 68 条脚本 RNG 访问，按原顺序比较原版实际观察到的前 64 条，另外 4 条未验收。没有按 VM 的 `0x4000` 标志剔除记录：该位也出现在实际运行的 VM 上，先前会得到零配对的过滤方式已拒绝。相同 Wasm 的审计关闭／开启短前缀，与旧观察模块的九份状态、相机、游标、HUD、VM／战斗载荷逐字节一致；这项透明性控制的范围为 1,200 回调。

比较器的前两次尝试均保留为失败。新观察器临时用主线程 DR3 观察 RNG，明确让出了该窗口的资源泵断点；旧比较器首先因缺少资源泵事件而拒绝。只补充下界后，它又在请求第 30,760 个 Player 时失败：把下一次 Player 的时间提前用作整次更新入口，令之前的 ANM 读取窗口越界 **702.5665 ms**。失败现场确认读取交付尚未发生、审计未溢出。

后续诊断在这一个明确缺失资源泵的窗口，使用前一次 Player 接收时间作为代表性帧入口，在第一次脚本读取前交付原版已经完成的恢复时间。原版寄存器读到的代次约束了这一顺序；没有补造资源泵事件，也没有向 C++ 注入原版 RNG 值或逐帧状态。**代表性帧入口不是已恢复的原版实际入口时间，读取代次分类确实使用原版观测值，不能改称普通独立调度通过。** 调用计数字来自观测内存，不声称它们也由停住指令的寄存器解码。

同时补充了一项观察器保护：其他线程的 DR6 已有硬件命中时，延后重设其调试寄存器，等待该线程自己的事件。自有无窗口双线程夹具中，清除另一线程状态的负例出现四条无命中标志的异常观察并以 `0x4000001e` 退出；延后更新的正例通过 256 个事件，执行 91 次延后且没有丢失标志。新的原版短预检和 35,000 回调记录均未触发该延后分支，因此**仍未证明旧原版启动故障的具体原因**。此前零回调超时、含两条未识别单步异常记录的一次进程退出及夹具记录错误均单独保留，没有放宽异常策略。

本记录的异常和 Initialize 门槛通过，Scene 严格门槛继续以未审核的诊断驱动拒绝；白名单和原有严格模式通过数未增加。旧 Normal 默认时钟记录的 RNG／活动弹差异仍保留，未由这份新记录关闭。普通独立运行、完整模式、原版整局画面／PCM、普通 GUI、浏览器实际操作与持久化及整作 1:1 继续。
