# TH14 覆盖层加载交付与 VM 调用前顺序

2026-11-04，正常动画与覆盖层动画均接入带 VM 身份的加载交付点；调用前通知在 VM 预更新回调之前执行。两个 C++ 文件合入本地，新核心为 a2f732df。[结构化复核](th14-overlay-vm-boundary-nov04.json)绑定本次源码、原版指令组件、实际 C++ Manager、录像、Application 和浏览器构建。

## 覆盖层入口

原版覆盖层 ANM8 的调用位置为 47e73b，正常 ANM29 为 47e65b。先前带身份回调只接入正常遍历；现在 GameBattle 将同一接口传给覆盖层遍历。旧的正常动画专用回调保留原调用范围，暂停恢复时已经执行过的覆盖层不会再次更新。

实际 Session 在覆盖层 file2／script16／layer34 的调用前和返回后，各触发一次受控失败，两次均以加载错误返回 Session。正常动画的两项倒退时间失败控制也通过。它们验证错误传播，不代表原版调度等价。

## 调用前通知的位置

原版 47e65b／47e73b 调用 46fe50 后，才在 46ff1f 调用 VM 的预更新函数。先前 C++ 通知放在预更新函数之后，与这个位置不符。现在通知先执行，随后才运行预更新及 VM 主体。

原版组件实际执行原函数，使用明确声明的合成 VM、栈、回调及标记，三组初值确认回调发生在调用前和返回后两个观察点之间；没有改写原版指令。实际 C++ Manager 在正常／覆盖层的六组检查中均符合该顺序，旧实现的六组控制全部被拒绝。这项组件验证不恢复历史录像缺失的线程现场。
