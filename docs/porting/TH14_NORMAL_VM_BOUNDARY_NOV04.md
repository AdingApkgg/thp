# TH14 正常动画 VM 边界与换关 RNG 交付

2026-11-04，独立 C++ 核心在正常动画 VM 的调用前、返回后提供带实际 VM 身份的加载交付点。灵梦 B Normal 的一份 35,000 回调原版记录，用同一次暂停事件的初始化时间及实测 VM 身份驱动，所选 32 字段、相机、HUD、1,057 行 VM 的 303 字段和 393 个战斗池检查点全部相同。[结构化复核](th14-normal-vm-boundary-nov04.json)绑定源码、原始记录、运行结果和检查器。

## 实现

AnmManager 在原版 47e65b 对应的调用前、47e660 对应的返回后传出当前 VM 和边界类型；没有包装或替换 VM 方法指针。旧的返回后回调重载继续可用。

GameBattle、GameSession 将边界接入实际加载器。调用前只轮询已经进入初始化阶段的任务，避免在选中 VM 即将执行时更换资源；返回后沿完整加载流程继续。宿主可在这些位置报告外部完成时间，失败沿 Battle 返回 Session。引擎不接收原版 RNG、子弹状态、序号或生命值。

本次观察输入匹配的对象由 C++ 自行创建，其身份与原版记录比较后才交付时间：

| 换关 | Player 回调 | file / script | 原版句柄 | 边界 |
| --- | --- | --- | --- | --- |
| 二面 | 14,082 | 5 / 16 | 720865 | 返回后 |
| 三面 | 30,749 | 5 / 4 | 696286 | 返回后 |

这份记录保留 4,244 个成对 VM 调用／返回事件和八个 worker 写入边界。三个可读 worker 现场与实际调用对象一致；三面最后一个写入前的主线程已在返回地址，不能把它描述为仍在执行 VM 方法。

## 使用同一次暂停事件的时间

每次最终写入事件先被新增辅助观察器记录，再被既有初始化观察器记录；两者之间没有恢复被调试进程。二面、三面的时间差分别为 611,900 和 867,800 ns，寄存器、栈、RNG 字节和回调计数相同。

早先适配器用较早的辅助时间交付 VM 输入，既有 worker readiness 却使用较晚的初始化时间，造成 deadline 已到而 worker 仍未就绪。现在两处统一使用既有初始化事件的时间。没有提前移动时钟，也没有修改 60 ms 等待。

新检查器重新生成唯一允许的适配器，复核原版对象身份、同一暂停事件和 C++ 实际交付状态，并保留原有异常、Initialize、Scene 载荷及时间检查。原有 v4 门槛继续拒绝未审查的自定义 Scene 驱动。此前 40,000 回调的 child-clock 假设仍未证明其原版身份，不能借用新记录的通过结论；其[冻结诊断证据](th14-replay-rng-order-nov04.json)保留原范围。
