# TH14：独立工作线程读取真实共享相机（2026-11-05）

Scene 相机复制现在有实际独立的读取端。候选把 Wasm 线性内存本身改为共享内存，Worker 按既有 75 字顺序读取活动的 C++ `SceneCamera`，不从主线程预先复制相机值。结果写入任务私有 SharedArrayBuffer，C++ 在完整就绪后接收、初始化并发布 incoming Stage。没有逐字 ACK，没有原版帧号／VM 完成目标，也没有写入原版相机或 RNG 观察值。

这是显式候选，默认构建开关保持关闭。原版调度、整局 1:1 和模式通过数均未因此通过。[公开元数据](th14-shared-scene-nov05.json)记录源码、计数、差异、路径及哈希；原始状态、游戏资产、录像、实际随机值／cookie 和二进制留在本地。

## 生产路径改变

`SceneCameraReadJobTh14` 增加读取提供方，原来的同步 overload 保留原行为。`StageResourceEffects` 默认仍直接读取活动源；`GameBattle` 将真实 Scene 阶段接到该接口，未完成的副本和 incoming owner 都保持私有，失败保持失败。原版顺序的 offset 映射没有改变。

SDL 候选以 `TH14_SHARED_SCENE_COPY` 选择独立读取方。下一关等待开始时预热 Worker，资源 Scene 阶段准备好后才交付源指针和 75 字布局。Worker 直接读取共享 Wasm 内存，只写自己的结果缓冲区，不写 C++ owner；完成后由主线程接收。完成、取消和新代次均隔离旧任务。准备阶段取消、旧消息、非法内存／范围／重复 offset 和源 owner 改变等边界有独立检查；普通浏览器中实际运行到一半的取消流程仍需验收。

原有 RNG 三存储和第四次全局复制继续使用上一候选的就绪／确认通道，真正的 RNG 状态写入仍在 C++ 主线程。**这部分实际并发与写入 owner 的取消等待是下一步重点，本次没有声称关闭。**

## 构建与实际运行

线程版 WASI 核心的 141 个玩法单元全部重新编译，零旧对象混用；加载／标题前奏的链接复用的只是这批刚编完、哈希绑定的 141 对象。GLES 浏览器候选另将 146 单元全部重编。两个实际 Wasm 的 memory 类型均检查为 shared，上一 GLES 候选保留为 unshared 反例；不靠 JS 控制缓冲区是 SharedArrayBuffer 就宣称 Wasm 内存已共享。编译使用本机固定 SDK 的 [线程目标](https://github.com/WebAssembly/wasi-sdk/blob/main/README.md)，浏览器构建使用 `-pthread`。

链接保留两条 Emscripten 库内部符号依赖警告及其汇总警告，没有隐藏或把它们写成零警告。共享代码和 WebGPU 分支共 9 项语法检查通过；这不代表其他标题或 WebGPU 运行验收。

## 严格失败继续保留

原始逐回调比较仍失败。主参考前 14,067 次回调的 109 字一致，第 14,068 次、二面加载期间，首先出现脚本种子和游戏随机调用数差异。

对另一份同录像的完整原版记录，唯一关卡／控制帧配对有 120,866 对。32 项状态仍只有脚本 RNG 两字段和活动弹数不同，弹数有 **90 处**差异；相机有 21 个字段存在差异，所选两项 HUD 无差异。上一独立加载入口候选同一额外参考有 26 处弹数差异，新候选不能据此称为修复；构建和独立工作线程完成时机都变化，也不做单因素归因。原始门槛与旧失败不覆盖、不放宽。

最后阶段在输入游标 26,089、声明 26,469 帧时自然结束，仍留 380 帧未消费输入；这不是已观察到输入文件 EOF。严格模式通过数不增加，旧版 16 份有限回归也不自动迁移到新的线程 ABI。

浏览器接口本轮仍只能列出已有测试页，读取页面时报连接不可用，因此没有浏览器 UI、跨关或 GPU 通过声明，也没有要求用户反复手动恢复。后续继续 RNG 实际写入／生命周期、普通原版 GUI、所有自机／难度、保存／离线、浏览器跨关／取消、整局像素与 PCM。
