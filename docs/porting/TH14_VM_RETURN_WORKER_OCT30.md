# TH14 普通 VM 返回边界的加载轮询 · 2026-10-30

加载已经就绪时，原版工作线程可能在普通 ANM 的一个 VM 返回后、下一个 VM 更新前恢复 Replay 状态。此前正式实现仅在整个普通 ANM 注册表入口轮询；本次增加每个实际 VM 更新返回后的可选轮询，位于退役和绘制链发布之前。加载器使用自己的时钟和就绪条件，不传入原版 RNG、VM 状态、对象句柄或固定拍数。

`AnmManager::update(bool)` 的原符号保留；新重载仅用于 TH14，不改变对象布局。GameBattle 仅在换关加载尚未完成时安装局部回调，并分别保留加载失败和动画失败。浏览器构建明确覆盖两个 AnmManager 文件。

## 已核实的范围

[来源与有限回归检查器](../../tools/th14-vm-return-review-oct30.py)和[哈希摘要](th14-vm-return-review-oct30.json)绑定实际构建与留存结果：

- 全新编译 146 个浏览器单元、141 个原生核心单元，源码与快照一致；未纳入工作区另行修改的 ResourceCrypt。
- 原版受控 33,000 回调窗口观察到 `47e660`，即实际 `46fe50` VM 调用返回位置。每线程各增加并恢复一次暂停计数，原工作线程自行执行 Sleep60、种子恢复和 globals 复制。当前核心能在目标 VM 返回交付该时钟；保留旧核心不能。
- 此受控记录的状态、HUD、651 行 VM、288 个战斗检查点和初始 2,870 次发布相同，但旧／新核心均有 17,039 行镜头字差异，严格门槛仍失败。受控调度不能证明此前独立交错已修复。
- 独立记录的 33,000 回调、629 行 VM、304 个战斗检查点、全部所选状态／镜头／HUD／发布仍通过严格复核。
- GLES／WebGPU 实际 Application 各 2,264 帧、七项断言、完整图像、状态、文件和 1,508,352 帧静音 PCM 与此前一致。这两个原生入口关闭后台 worker 功能。
- 当前浏览器候选通过短回放自然结束，并以普通输入观察到咲夜 B Hard 五至六面换关及六面 Boss。该版本后续自然结束和刷新持久化没有留存证据，不继承其他构建的结束验收。

## 保留的诊断和失败

[Scene／启动绘制窗口诊断](TH14_SCENE_PUBLICATION_WINDOW_OCT30.md)另行说明推定宿主时点、实际首个签名创建调用及颜色缓存观察。推定时点即使使所选字段相同，默认严格复核器仍明确拒绝。新原版记录没有复现旧一字缓存失败，不据此关闭历史失败。

新增的普通 ANM 调用边沿观察，只在工作线程 Sleep60 至 Replay 恢复的窗口记录实际调用／返回，不显式控制线程。一次晚到返回事件的失败保留，修正后的记录和实际处理器 AST 控制均验证排空逻辑；停止后主线程 PC 不是同时刻采样，调用边沿也不能代替 VM 内部的精确指令位置。

普通原版冷 Replay、独立加载／RNG 交错、五个后续关卡入口组合、整局图像／PCM及全部模式仍待闭合。覆盖保持 30／25，`completeGame=false`、`nativeEquivalent=false`。源码增量仅含源码、工具、文档与哈希；原作资源、录像、内存、图像、PCM 和二进制继续留在私有 artifacts。
