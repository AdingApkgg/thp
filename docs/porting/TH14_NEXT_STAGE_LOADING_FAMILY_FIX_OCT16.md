# TH14：恢复分阶段换关的加载动画（2026-10-16）

新的保留世界换关路径通过 `prepare_stage_phase` 分块准备资源，绕过了旧 `prepare` 路径中创建加载动画的调用。换关能完成，但原版持续运行的 `ascii.anm` 17／16 号加载动画家族没有运行，其视觉 RNG 消耗和画面也缺失。

`GameBattle` 现在在普通下一关请求时创建实际加载家族，在实际关卡激活时广播 interrupt 1。使用原有 `LoadingTh14` 与真实动画脚本，不增加手写 RNG 消耗或采样值。只修改 `GameBattle.cpp` 与 `GameBattle.hpp` 的 TH14 条件分支；初始进入、旧 SDL boot 加载和其他作品的实现没有重写。

## 定位与验证

公开灵梦 B Normal 录像的原版前 20,000 个物理 Player 回调中，最早活跃差异是二面第 2,144 帧少回收一发子弹。新增两个只读窗口共 77 帧后，奖励、敌人、阶段参数、伤害区域和物品字一致；第一处是弹槽 201。其前一帧的动画字段只在旋转 Z 上不同：原版四角最高 Y 约为 `15.996456`，移植版约为 `16.233704`，严格的上边界为 16。差异随后改变空闲弹槽的复用顺序。

实际读取该原版子进程中的 ANM 原始状态后，将同样的几何输入分别交给原版 `0x479560` 与当前生产几何函数：2,781 组、33,372 个原始字全部一致，严格边界判定差为零。原版函数在 Unicorn 中执行，仅安全 cookie 检查受控；这不是实际原版游戏中 quad 输出或物理 GPU 的采集证明。因此本次没有改动已经匹配的几何函数。

沿视觉流回溯，原版在加载窗口每四次回调生成一次实际粒子，每次消耗 24 次视觉原语；旧新队列核心缺少整个加载家族。在声明的 60Hz 时钟下，175 个连续回调的视觉消耗增量从旧版总计 340，恢复为与原版相同的 1,252；完整逐回调增量保留。该样本的 seed 初始化仍比原版早两个非活跃回调，跨过一次粒子生成，故二面视觉 seed 仍相差一组 24 次原语；没有通过改写计数或 seed 补齐，也不称视觉流已经相等。

冻结已发布源码，只加入上述两个文件的变化，重新编译全部 141 个核心对象与 146 个 SDL 对象。完整 30 份公开录像矩阵实跑 2,853,648 次回调，仍为 27 份自然 EOF、3 份 Game Over，每份终止位置与回调长度均未变。所有 raw32 字重新比较：视觉 seed／计数字差和 225 个弹数字差完整保留，其他 29 个所选字段及全部活跃／owner 字节不变。六份 Extra 没有普通换关，其完整输出全部不变。这里的矩阵不是全部原版整局对照。

全部 141 个核心对象重新进行不恢复的 ASAN／UBSan 插桩，三份既有失败输入共 212,679 次回调与候选非插桩版的 raw32、活跃标记、owner 字节完全相同，未发现插桩错误。三份仍然是 Game Over，没有将插桩通过写成回放通过。共享源的 TH13／TH16 单元编译在修改前后均因未改动函数的 `cancel_all_th14` 符号失败，结果保存，不计作其他作品编译通过。

新 SDL 为 1,892,277 字节，SHA-256 `f798639ddabdc0be3b278dbf56fed2b43e4a27b78b964f8f9cddff5d3b4fb4ec`；导入／导出接口与原版发布模块一致。之前发布的逐文件 IndexedDB 保存 helper 字节未变，并使用新 WASM 重新运行真实 Emscripten／IDBFS／IndexedDB 九项控制，全部通过；测试数据库独立，不访问已有游戏存档。冻结 Launcher 图保留，127 个站点路径只改变模块、相应运行时声明／外壳和缓存散列。

本机仍固定 `http://localhost:8208/`，外层与游戏页面默认静音，原四份录像保留。新模块实际从一面播放公开灵梦 B Normal，已经自然进入四面；截图与选片日志单独绑定，不继承旧模块的浏览器结果，也不把画面中的 180 诊断计数称为实际三倍游戏速度。
