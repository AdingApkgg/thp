# TH14 实测 pump 与首次脚本读取边界（2026-11-05）

在已公开的实际 RNG 指令读写观测基础上，增加两种只用于观测的硬件断点安排，原版和模型的有限检查都已结束，没有继续运行的原版采集进程。

StageVM 调用／返回断点轮换后腾出 pump 断点：35,000 回调、零报告调试异常，实际记录第二面 50 次、第三面 31 次 pump 和 1,021 对 VM 调用／返回。自有双线程组件先验证每类 256 次事件、无未知断点，保留 ASLR 和链接器合并导致的早期组件失败。该记录的首读仍未重现旧争用负例。

另一个安排只在 RNG 观测窗口内将 DR0 在 Player 入口与 pump 之间切换；DR1／DR2 保留 VM 边界，DR3 保留数据观测。自有双线程组件每类 256 次事件通过，挂起其他线程前继续保留待处理 DR6 的保护。原版记录 35,000 回调、零报告调试异常、6 个切换边界和 64 次实际脚本 RNG 指令读写。

该记录直接观察到同一主线程顺序：最近 Player → pump → 首次脚本读取。Initialize 恢复完成的回执在这个 pump 之前；比较器因此不安装多余的首次读取等待，保留实际 Initialize 阶段及所声明的时钟／pump 输入。没有把上一 Player 时钟冒充当前物理帧入口，也没有将原版 RNG 值输入引擎。

有限比较中 32 个状态字段、2,624,925 个相机字、回放游标／HUD、64 次实际指令值和计数／顺序、728 行各 303 字 VM、347 个战斗检查点（50 个非空）一致。模型另有 26 行脚本审计输出，仍不接受为对应原版读取。未以 `0x4000` VM 标志排除活跃脚本。

局限保留：DR0 切换依赖已假定的原版分发顺序，不能证明所有未观测的 Player／pump 调用都被捕获；调试回执时间不是原指令执行时间；同线程顺序不证明跨线程精确交错。相机的发布前缀安排仍含从混合副本推导的部分。Initialize 严格检查通过，Scene 因未审阅驱动继续拒绝，白名单和严格通过数未改变。

旧 Normal 默认粗时钟失败、旧首读争用现场和独立线程调度均未关闭，两个新记录不是旧失败的替代。Player 回调计数不能单独确定物理帧入口。整作 1:1 未完成。
