# TH14 启动堆跟踪与释放入口修正

原版 `0x4854fe` 跳转至 `0x4855d2`，但后者也有直接调用者。对实际原版指令做的[独立组件执行](th14-crt-common-free-site-nov03.json)确认两个入口都可到达 `KERNEL32!HeapFree` 边界，空指针会返回；系统堆本身由声明的合成边界替代，并未执行。

分别启动两个静音原版进程，观察调试器已跟踪线程从附加后至一面 600 个 Player 回调的有限窗口，两次均无报告调试异常。旧入口记录 708 次 CRT 分配返回、44 次释放入口、32 次敌人分配返回，其中 698 条事件发生在观察器记录首个 Player 回调之前；同线程有 91 次分配地址再次出现前未见释放。修正后的共同入口记录 708 次 CRT 分配返回、281 次释放入口、32 次敌人返回，935 条事件发生在观察器记录首个 Player 回调之前；仍有 13 次同线程重复地址未见释放。两个独立进程的调度并非严格相同，不能把这些数字的差值解释为唯一因果关系。[旧入口摘要](th14-crt-boot-heap-trace-nov03.json)、[共同入口摘要](th14-crt-common-free-trace-nov03.json)不包含运行时地址。

每次仅按同线程匹配地址；直接系统调用、附加前活动、跨线程实际内存顺序，以及释放调用是否成功均未证明。硬件断点会影响调度。采样未向候选引擎传递原版地址，也未修改生产玩法；仅清除了预先声明的暖启动 attract 标志。此前主线程堆模型的生命周期输入遗漏了可能绕过旧入口的释放，不能用于声称完整堆重建。原版完整堆历史、`worldZ` 字差及整作 1:1 仍未解决。
