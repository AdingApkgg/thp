# TH14 启动与随机种子诊断

当前整作 1:1 未完成。这条诊断用于追踪启动的资源与 ANM 创建顺序，补充全流程记录缺少的 RNG 调用来源。原版冷启动诊断已在声明的时钟输入为零时执行到种子写入；该冷启动路径的后续字体及 ANM 初始化仍未走通，不能据此调整生产种子或固定等待帧数。

2026-10-15 另实际运行了当前生产源码的私有观察器：初始时钟为零，固定 60Hz 回调及四次普通菜单确认，527 次回调后完成首关 48 次更新。1,878 条原始调用的数学、顺序和回调边界经独立复算均一致，其中构造阶段字体 256 次 `next16`、成绩初始化 494 次 `next16`，后续视觉／ANM 1,128 次 `next32`。第 479 回调的玩法计数 494→0 是实际关卡初始化，种子未变；没有用额外调用补齐计数。[独立记录与范围](th14-short-title-rng-independent-summary-oct15.json)。

这份记录沿用真实 GameSession／ANM 函数及初次资源队列的提前返回顺序，资源准备和绘制使用声明的无设备接口。它没有真实 SDL 上传、音频输出或原版同输入标题记录，不能直接对照既有 Native 1,336 次调用。诊断脚本曾提前释放引擎借用的 DAT，导致首次资源读取失败；该失败与 750 条构造记录原样保留，修正只延长输入内存寿命，复用同一编译模块。成功运行末整份 90,776,747 字节 DAT 的内存哈希与输入相同；独审只绑定这一运行时测量，不声称重读了已退出进程的内存。生产归档、种子与 RNG 算法均未因此修改。

另已复核完整原生采集的来源：它从真实进程的标题吸引演示进入首个 Player 快照，保留实际时钟与先期加载状态；当前 headless 则默认时钟零、直接进入选定回放，未执行同一标题及初次异步加载。首个 Player 观测边界相同，不代表先期输入及生命周期相同。现有绝对 seed／calls 字差保持失败，但不能仅据此认定 RNG 算法少调用。[只读来源审查](../../artifacts/th14/callback-registry-static-review-oct14/warm-initial-rng-origin.json)保留生产器行号、快照及原始首帧绑定。

字体循环已由既有原码记录确认恰好消费 256 次，与当前实现相同。另一份旧启动记录已将 1,360 次调用全部分类，其中 `ascii17→ascii16` 加载动画的 45 个孩子各消费 24 次；孩子数量由那次真实加载时长决定。该旧分类不能直接套作当前 1,336 或差值 1,056 的逐调用解释，也不能成为固定补调用次数的实现。后续应在同一时钟及加载事件输入下比较具体动画的调用顺序。

诊断在 Unicorn 中映射固定的 TH14 1.00b 原码和只读 DAT 输入，从真实 `488e04` 堆初始化函数及 `4449f0` 回调入口推进。普通函数体执行原码；外部 API 使用明确受限的声明环境，未知请求保留现场并停止。它不是从 PEEntry 完成的原生冷启动，也不使用先前运行的内存快照。

已有实际结果：

- 原码在初次分配/释放后解出 `THA1` 头；[独审](../../artifacts/th14/startup-bounded-file-independent-review-oct14/review.json)逐项重建全部 34 次早期堆访问。
- 只读文件服务交付原文件头 16 字节和目录尾 2,932 字节，共 2,948 字节。原码完成 5,632 字节目录解压；[独立镜像](../../artifacts/th14/startup-directory-mirror-audit-oct14/receipt.json)完整哈希一致，目录包含 227 条记录。
- [原有限预算及严格边界结果](th14-startup-readonly-file-directory-observed-oct14.json)保留 50,000 次观察停止和后续压缩块末尾预读的检查失败。观察次数包含代码 hook 看到的停止指令，不等于全部已经执行的指令数。
- [预读续行记录](th14-startup-prefetch-continuation-observed-oct14.json)分别保留错误连续字节绑定的失败和修正后的结果。续行仅允许明确记录的一次物理补齐字节读取，并实际核对原码的比较、分支与清零；未补零、未修改原码或初始化补齐区。
- 后续声明的 FS 段和最小线程信息块允许原码维护 SEH 链，零地址页保持未映射。字符串扫描的补齐读取另行记录，并要求原函数返回到原调用者、栈位置一致及 EAX 为零。它们不能作为原生堆布局、越界不故障或 C++ 内存安全证明。
- 原码解析目录、关闭并重新打开资源文件后，在格式化 `th14_%.4x%c.ver` 时暴露尚未初始化的 CRT 线程依赖。后续诊断执行真实 `48bd06`，由原码写入编码后的 FLS 函数槽、分配 956 字节线程状态并初始化成员；该阶段经过 772 次代码 hook 观察返回 EAX=1，含之前堆初始化的累计观察数为 779。受限线程局部存储与临界区只维护明确的单线程逻辑状态，不制造原生临界区结构字节；直接访问该私有结构仍会停止。
- [CRT 线程链诊断](th14-startup-crt-thread-chain-observed-oct14.json)确认版本资源的 130 字节读取，文件服务累计交付 3,078 字节。该版本在 `446377` 的数学库调用前停止，旧记录保持冻结。
- 后续映射固定 D3DX 原码并执行真实数学函数；[真实视口 owner 记录](th14-startup-viewport-owner-prefix-observed-oct14.json)确认原版函数写入 640×480、缩放 1，八次数学调用实际返回的 128 个矩阵字均为有限值。声明的 DLL 分派及 FPU 配置仍不是实测原生 CPU 环境。
- [同输入数学比较](th14-startup-camera-same-input-math-observed-oct14.json)把上述八组原始参数直接交给冻结的当前数学实现，128 个输出字全部一致。此项只比较这些参数下的运算，不证明屏幕相机默认参数或整作一致。
- [主线程与节点记录](th14-startup-main-node-prefix-observed-oct14.json)保留原版时钟与种子写入，以及未初始化节点 flags 的严格失败。后续明确记录的一次 flags RMW 保留物理 poison，并核对原码低两位写入及返回；声音工作线程只登记为待执行，实际执行指令数与音频输出均为零。
- [原版回调表构造记录](th14-startup-original-registry-prefix-observed-oct14.json)执行 WinMain 中的真实分配、构造与全局发布切片，随后主线程节点注册真实返回。切片在下一分配前停止时已有一个参数压栈，不是函数返回。再推进在 `47b9ff` 因 ANM manager owner 尚未构造而停止；未手动填入该全局指针或伪造链表。

完整堆访问以计数和顺序哈希保存，但只保留前 4,096 个逐项记录；超出部分没有被独立逐项重建。目录数据的完整哈希比较与该访问日志范围是两项不同证据。

这一系列诊断没有启动零售进程、加载 Win32 服务 DLL、创建实际线程、打开音频设备或写入原版文件。生产加载器、渲染器、混音器和发行 WASM 均未因这条诊断修改。本机浏览器测试入口保持 `http://localhost:8208/`，输出默认静音，详见[本机入口](TH14_LOCAL_WORKSPACE_CURRENT_SERVER.md)。
