# TH14 旧存档字节视图修正 · 2026-10-18

旧 IDBFS 成绩记录的 `contents` 实际为 `Int8Array`；加载后的比较基线为 `Uint8Array`。旧增量提交器逐项比较数值，将同一个物理字节的 `-128` 与 `128` 判为不同，导致实际游戏周期存档反复报告另一个窗口已修改。此前九项隔离控制没有覆盖这种旧记录，不能证明实际生命周期无误。

`browser-save-delta.mjs` 现在将视图的底层区间按无符号字节比较，保留 `byteOffset` 和 `byteLength`；基线仍独立复制。逐文件增量、同一事务内远端核对、真实冲突中止、显式删除保护和串行提交保持有效。未用时间戳或诊断哈希代替内容比较。

同一份浏览器检查分别运行旧、新提交器，使用两个真实 Emscripten 文件系统、真实 IDBFS 和不同的隔离 IndexedDB。旧版完成前十项后，在应成功的有符号基线更新处复现错误；新版十三项全部通过。新增控制覆盖原版错误负对照、有符号基线更新、相同物理字节不重写，以及远端确实不同仍中止。原有九项并发、删除、原子回滚及提交中修改控制继续通过。事务 abort 是显式故障注入，不是真实容量不足。

实际同源游戏窗口确认旧成绩为 `Int8Array`、基线为 `Uint8Array`，随后成功提交新成绩；首次成功后继续观察 601.503 秒，无警告或错误。另一个管理窗口重新读取后仍列出四份录像，读到的成绩条目对应一次成功提交。两窗口均保持静音。此次实际运行使用只增加 console 日志的私有观察外壳，比较、事务与队列逻辑不变；日志中的 FNV 仅用于诊断，不是内容相等判据或导出字节证明。没有导出新成绩，也没有中途重载游戏。
