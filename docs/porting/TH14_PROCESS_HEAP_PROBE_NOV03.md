# TH14 敌人同尺寸对象的独立进程堆实验

原版敌人工厂请求 `0x530c` 字节，并经 CRT 调用当前进程堆的 `HeapAlloc`。为了解不能用固定基址平移解释的地址差，另行构建了一个独立的 32 位 Windows 控制台测试程序；它不启动原版，也不使用原版录像或资源。

六个独立测试进程各执行八次 `0x530c` 字节分配，依次释放下标 1、3、5、7，再执行四次同尺寸分配。六次中所有 `HeapSize` 均返回请求大小，四次释放均成功，四次新分配均复用被释放的位置；复用下标顺序均为 5、3、1、7。首次连续分配的相邻地址差在这六次中均为 `0x5318`；六个进程的堆句柄和首块地址各不相同。[复算摘要](th14-process-heap-probe-nov03.json)只发布相对差值和计数，不发布原始指针。

另一组六个独立进程使用 `HeapLock` 和 `HeapWalk` 在释放前、释放后及重新分配后记录自身堆。最后一个待释放块与其后的空闲区域在释放前分别列出，释放后显示为一个更大的空闲块；这与该组实验中的相邻空闲块合并一致，但不足以确定堆内部算法。第一次枚举的 512 项上限不足并按失败保留，扩大到 4,096 项后六次完成；首个成功进程的枚举最多 719 项。[枚举与限制](th14-process-heap-walk-nov03.json)不包含原始地址。

这是本机和此测试程序自身堆历史下的有限结果，不证明 Windows 堆算法或顺序稳定，也不复现原版程序启动、资源加载及其他分配的历史；不能据此确定原版敌人地址、把这些地址传给引擎或关闭 `worldZ` 字差。首次尝试使用仅支持 Wasm 的编译器失败，失败日志保留；随后使用本机 MSVC x86 编译并实际运行。整作 1:1 未完成。
