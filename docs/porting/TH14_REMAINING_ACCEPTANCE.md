推进规则：优先首个真实玩法／流程差异；先最小窗口，修复后只重跑受影响完整用例。只有新增变更或失败需要时才重复验证。每项通过时记录版本、输入与实际范围，不以采样字数代替完成度。

完整录像对照现使用 [复用工具](TH14_CAMPAIGN_TOOLING_OCT25.md)，从哈希绑定对象重链接仓库内夹具；迁移已按完整 Hard 用例逐输出核对，避免继续逐模式复制私有脚本。

此前工具退出码遗漏相机、HUD、动画和分配窗口的失败门槛，已补齐；Lunatic 的旧退出码 0 不作为完整通过。清单现保留每个版本额外门槛的结果，缺少报告写为未知。下一步直接观察原版 `436be7` 读取加载标志后的 `436bed`，将控制器时刻与 Player 时刻分别记录；新增观察入口目前仅完成语法检查，尚无运行验收，不从旧记录推算或拟合这一时刻。

时间估计尚不能收敛为可信日期：已知差异修正和完整模式覆盖仍需数天；严格整作 1:1 还可能需要数周，取决于完整用例暴露的新问题。此估计不是完成承诺。下一次估计依据是完整模式清单中剩余首差的数量与性质。

采集及运行包遵守 [存储约束](TH14_STORAGE_POLICY_OCT25.md)：单次观察预算 2GiB，至少保留 100GiB 可用空间，复用固定资源，不启动无界接续队列。原始资产、录像、内存与二进制测试产物不随源码发布。
