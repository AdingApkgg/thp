# TH14 背景采样与实际绘制函数对照 · 2026-11-13

此前首帧整图的整数偏移相关性不能直接证明几何偏移：原版背景年龄85，当前基线81，滤波候选80，实际 UV 也不同。不得平移画面、补更新次数或注入参考 UV 来接受该比较。

先检查已执行的独立 D3D9 HAL／ANGLE D3D11 采样任务。三个实测 UV 相位分别执行 POINT／LINEAR，同组使用相同原作 ARGB4444 纹理、人工全屏顶点和纯纹理 shader。保留的六对640×480 BGRA 文件逐字节相同，共1,843,200像素、7,372,800通道零差异。这证明这些固定输入下两个采样实现一致，不是实际合成路径或整个生产 Renderer 的验收。

原任务在结果序列化处存在 `sha(Path(__file__))` 类型错误；所有原始像素已写入，但没有最终报告。检查时该脚本进程已不存在，原退出码不可用。保留执行版工具，另写 `retained-pairs-audit.json` 从原始文件重算差异及哈希，不重跑 GPU 任务，不宣称未知退出码为0。代码已修正为读取工具字节后计算哈希；清理块位于序列化之前，但其完成没有独立收据，不能补写“全部设备已回收”的证明。

进一步执行原版 `478f60` 绘制入口及其真实几何／材质分支。参考侧使用保留的 type0 第五嵌入 VM，重定位精灵纹理服务身份；显式固定相机 offset=0、viewport=640×480。D3D设备、批次入队／提交与 cookie 是声明边界。早期 v1 沿用共享夹具的 offset=(.37,-.61)，结果顶边为-1.5；这不是实际游戏相机测量，不能据此修正生产坐标。v2 明确使用零偏移，两版记录均保留。

移植侧使用当前141个正常权限游戏提供者，独立设置相同的可见绘制输入，执行实际 `AnmRenderer::draw` 和 `flush`。没有向游戏注入原版 VM。三个 UV 相位的四顶点位置、颜色、UV 共84个32位字段逐位一致；三组各八个混合／采样／寻址／深度状态相同。原版和当前代码都提交1280×960背景四边形，左上(-.5,-.5)，使用 LINEAR、Repeat 及相同混合状态。

结论：本组输入没有发现背景几何、UV加法或材质映射错误，也没有发现相同 UV 下的独立采样差异。暂不改通用 shader／几何，不恢复已证实错误的合成滤波判断。整帧候选281,902像素差异仍失败；旧基线194,921像素差异也仍失败。实际中间目标、批次提交状态和加载更新相位仍需在相同生命周期边界核对；24次加载 RNG 差异和全部整作验收继续开放，`completeGame=false`。
