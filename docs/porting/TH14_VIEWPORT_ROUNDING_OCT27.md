# TH14 实际绘制的视口取整修复 · 2026-10-27

生产 WebGPU 与 GLES 着色器现在先加上完整视口平移，再按 1/256 像素取整，最后换回局部坐标。原实现先在子视口局部坐标中取整，二进制浮点的边界结果因而不同。它改变纹理坐标插值，少量线性过滤权重随之跨档；差异在混合之前已经存在。

此前实际 Application 第 2,264 帧、第一段自动演示三面战斗第 241 帧，在两后端间保留 14 个像素、16 个通道字节差。新独立 D3D9 对照发现，其中六字节取 GLES 的值，十字节取 WebGPU 的值，另外还有两后端共同的九个 alpha 错误。没有预先把任一后端当作参考。

## 实际调用与独立设备对照

[私有采集准备工具](../../tools/th14-prepare-application-trace-oct27.py)从冻结的生产源码生成观察版，只采集这一帧。119 份初始 GPU 颜色资源、原始 C++ 状态／顶点／实例数据、448 字节后端数据包，共 1,249 个事件和 47,336,648 字节去重私有缓冲。观察版的完整输出与原先实际 Application 缓冲逐字节相同，没有把参考值提供回引擎。

[独立 HAL 工具](../../tools/th14-application-trace-hal-oct27.py)在自有隐藏设备重放 416 次绘制和七次清除。它使用原始 C++ 语义输入及实际矩阵，通过 D3D9 固定管线执行；初始深度未知，只允许实际清除后使用。初始颜色来自被观察的 GPU。这是独立 API 控制，不是原版普通 Application 整帧采集。

第一次偏差出现在第 192 次绘制：目标 9 在绘制前的两个完整颜色缓冲相同，绘制后出现 51 个 alpha 字节差。第 230 次绘制引入原先 `(361,211)` 最早争议像素，随后经过目标 9→10→1 的复制。两次都使用 BGRA8 纹理 97，不能归因于打包纹理展开。

进一步保留实际 `ProcessVertices` 输出，并在自有浮点目标上观察关闭混合／深度后的源片段。透明度差异已经存在。合法的 `ps_2_0` 固定顶点管线 UV 观察另关闭后置雾，再与 WebGPU UV 读回比较；原始状态恢复后的完整帧哈希不变。早先不兼容的 `ps_3_0` 尝试、一次汇编失败、尚带雾的 UV 观察均保留并排除在 UV 结论之外。Shader Model 3 与固定管线的兼容限制见 [Microsoft 文档](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/shader-model-3)。原生专用可写顶点存储观察也不计为浏览器能力。

## 修复与范围

| 对照 | 修复前 | 当前生产代码 |
| --- | --- | --- |
| 同一实际 Application 图像，WebGPU 对独立 D3D9 | 15 像素／15 字节差 | 1,228,800 字节全部相同 |
| 同一实际图像，GLES 对独立 D3D9 | 17 像素／19 字节差 | 仍有 8 像素／10 字节差 |
| 实际 C++ → Emscripten／Asyncify → JS WebGPU Stage 回归 | 21／21 | 21／21，25,804,800 字节全部相同 |
| 当前实际 C++ GLES Stage 回归 | 历史单蓝字节失败 | 仍为三面 1199 帧 `(144,373)` B=119／120 |

WebGPU 私有单行实验首先得到完整原生相等，随后直接使用正式着色器再次通过相等门槛。重新编译实际 Application 平台层后，未经观察钩子的当前 WebGPU Application 也生成同一完整 D3D9 缓冲。因此结果包含实际应用和实际 C++ Renderer，不止着色器镜像。

两条当前生产路径均完成三次演示循环，各 17,545 帧、30 项断言、13 个动作。七份完整图像中六份相同，第一份演示就绪画面保留上述 GLES 十字节差。实际静音 PCM 数量各 12,681,216 帧。

完整回归没有通过：WebGPU 日志有 4,243 行，GLES 有 4,239 行，第二次演示的首个索引差异在第 2,707 行，分别记录 Application 11,210／11,211 帧，所见分数开始不同；静音 PCM 的累计哈希也不同。两条路径最后都返回标题，动作终态相等不代表中间状态相等。原因尚未证明，没有通过重新选择运行来消除这个反例。

[比较器](../../tools/th14-application-render-pair-check.py)现在先保存完整图像／日志／PCM 的负向诊断，再维持失败退出；各类相等门槛都保留。旧完整回放的八幅图像、日志及 PCM 在更新后的工具上回归通过，没有重跑旧整局。完整当前结果由[范围报告](th14-viewport-rounding-verified-oct27.json)绑定。所有图像均按四通道完整字节比较，没有容差或 alpha 排除。

本轮另对 225 份已结束采集的自生成缓冲执行 NTFS 透明压缩：351,879,168 字节内容的分配空间减为 134,782,976 字节。全部哈希、路径、大小和修改时间不变，保留 100 GiB 空闲保护，没有删除观察数据。
