## 实际发现的失败与修复候选

在新页面的录像管理点击该文件，界面显示“无法解析录像”，提示 `Error: 不支持的操作`。原因是网站发送 `playback / inspect`，而 TH14 运行壳的 command switch 没有 `playback`。该失败保留，不因本地菜单重开成功而抹去。

新增 `ReplayDescriptionTh14.hpp`，使用实际原生 `Replay::open` 校验／解码，提供 Shift-JIS 名字字节、机体、武器、难度、分数、时间、模式和已验证关卡／帧数；壳的 `playback / inspect` 调用该 C++ 导出。拒绝非法路径、非录像路径、空／过大文件和原生解码失败，并释放临时输入缓冲；元数据错误不修改活动 Application 的错误状态。

本地集成检查通过 60 份既有录制容器、一份实际普通菜单录制、三个无效文件及路径拒绝用例。测试执行实际 command 函数和编译后的原生 C++ 解码器。正常浏览器候选包仅重编 Application 并验证其余 145 对象，导出检查通过；Wasm 为 `f0257a17…`。

**候选尚未部署或浏览器复验。** `open`、暂停、跳转、倍率等独立录像工作区协议仍未接入，不能称该入口已修好或可播放；下一步补齐相关协议，再用同一浏览器持久化录像验收。线上基础菜单仍可进入游戏。

另外，首次加载发现通用的“下载约 1MB／尝试断网”提示不适合 TH14。网站分支的候选改动只为 TH14 使用已有本地化的“准备 TH14…”文案，保留实际请求／进度显示。现有 transfer 模型和挂载界面共 32 项测试通过；未声称新提示已在线显示。
