# TH14 录像终止与录入帧用尽观察点（2026-11-03）

原版 `455180` 读取回放输入时有两条不同路径：三个输入字均为 `FFFF` 时进入 `45521b` 并请求回放结束；当前关的输入游标不小于声明帧数时进入 `4552cd`，清空本次输入并继续递增游标。后一分支本身不请求回放结束，因此**输入用尽、看到结束菜单和完成整个录像不能互相替代**。

对两份新的魔理沙 A Normal／Hard 公开录像，先用原版解码指令与独立镜像核对，再遍历其 12 个关卡段的全部录入帧，未发现三个 `FFFF` 的标记。这只是文件内容检查，不能证明任一录像已在原版播放到相应关卡或结束。[扫描范围与哈希](th14-replay-input-terminal-scan-nov03.json)不包含录像内容。

新增只读[观察器候选](../../tools/th14-native-terminal-marker-observer-nov03.py)：在首批分配跟踪结束、且不与换关观察冲突时，为主线程设置对应硬件指令断点；记录实际命中的关卡、游标、声明帧数和是否恰好位于边界。每关输入用尽最多记录一次，首次终止标记后关闭对应断点。未启用观察的窗口或未命中都不能证明该事件不存在；不把观测值写入引擎，也不改原版指令。

原版指令组件覆盖标记正例、四个非标记反例和输入用尽分支；另有七种合成调试寄存器分配控制，以及两条事件处理路径各一正三反的合成内存控制。[独立复核](th14-replay-terminal-observer-unit-nov03.json)保留全部范围。它们不等于真实进程命中；观察器在投入长录像前另需短原版试运行，并继续遵守静音、存储与异常门槛。当前没有据此声称源录像 EOF、整关通关或 1:1。
