# TH14 绘制摄像机发布处的加载交付

TH14 现在能在绘制回调发布摄像机之后、透视计算之前推进已就绪的加载 worker。原版背景 `40e365`、前景 `40e7f1` 位于保存摄像机的复制之后，`446400` 的透视计算之前；worker 的 `40d435..40d447` 可以在此读取保存的 right。此前 C++ 将发布和透视连续执行，缺少这一交付点。

实现通过 `GameSession::draw`、`GameBattle::draw` 把已有加载器连接到两个实际发布位置，使用已有宿主时钟和资源就绪状态。跳过绘制和淡出到 60 的分支遵循原版条件，失败沿现有错误路径返回。五个游戏文件的行为变化限定 TH14。

50 组原版指令组件执行前景／背景分支及 worker 复制，其中 36 组经过发布位置。摄像机和 CPU 交错为合成输入，renderer flush 作为组件边界。实际 Wasm 的 200 组组合覆盖发布、跳过、等待和失败；72 次受控复制在旧核心中读取到不同的 right，修复后全部与原指令一致，72 组失败返回均传播。

141 个核心单元全重编，三份留存记录重新通过原有异常、Initialize、Scene 和原始载荷门槛：

| 灵梦 B Normal | 122,537 | 2,586 | 1,294 |
| 灵梦 A Extra | 38,403 | 860 | 46 |
| 咲夜 A Extra | 38,977 | 6,461 | 48 |

实际静音离屏 Application 经普通菜单进入录像，完成两关加速、换关和暂停：2,289 宿主帧／27 项断言、2,289 次呈现通过；两幅完整检查画面、1,526,784 帧离线混音哈希与封存参考一致。物理音频设备打开数为零。TH12／13／14／16 的相关单元共 12 项语法检查通过，浏览器目标 146 单元全重编。

本次交付点覆盖整次绘制摄像机发布后的窗口。逐字 REP 复制、透视函数内部写入、旧记录未观察到的线程顺序及旧 RNG／相机失败继续核对。三份有限记录不证明全部模式、源录像 EOF、整局原版画面／PCM、独立调度、浏览器游戏流程或存档等价，整作目标保持进行中。
