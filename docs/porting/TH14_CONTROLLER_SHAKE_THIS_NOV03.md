# TH14 震屏销毁后的控制器栈来源

此前把震屏回调销毁路径留下的未知地址称为“回调节点地址”。新增原版现场证据表明，在此次实际捕获的路径中，控制器读取到的是**外层震屏对象的 `this` 地址**，不是被删除的内部回调节点地址；此前这一对象归属的描述需要更正。

静音原版诊断运行 36,823 回调，在 Bomb elapsed 18–40 窗口记录 23 次控制器读取、13,013 次栈写入，以及一次内部回调节点删除入口。该次读取、删除入口保存的外层对象和 `RtlLeaveCriticalSection` 保存的 ESI 相同；节点地址与外层对象不同，调用返回地址与实际原版代码一致。原版音乐和音效主音量两次读取为零。

额外以四组互不相同的合成对象／节点地址执行原版 `46d180 → 46d450 → 401630 → 4016c0` 及固定版本 ntdll 的 `RtlLeaveCriticalSection` 指令，均得到外层对象地址。CRT 释放和未竞争锁的进入是声明的模拟边界，不是 Windows 堆分配器全程仿真；调试器暂停会影响现场时序。

这只确定该路径的地址来源。独立 Wasm 的对象分配地址与原版 Windows 进程不同，便携堆地址模型尚未实现；未把采样地址输入引擎，也没有改变生产玩法。VM Z 字、旧 RNG 交错、其余栈写入者及整作 1:1 仍未闭合。[复核元数据](th14-controller-shake-this-nov03.json)不包含原始内存或录像。
