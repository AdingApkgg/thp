# TH14 初次关卡 STD／ECL 后台解析

2026-10-29。初次关卡 worker 在归档解压和 ANM 解析之外，现在执行实际生产 `StageResource::open` 与 `EclResource::open`。有界数据包将已解析的场景对象、指令、ECL 文件字节和子程序描述交给主线程。GPU 上传、动画模板准备及 ECL 程序定义组装仍由原来的所有者执行；没有加入固定帧延迟或写回期望游戏状态。

## 交付与包含依赖

`StageEclTransferTh14.hpp` 沿用显式小端整数／浮点位、版本、总长度、来源标识和负载校验。传输不包含指针或 ABI 填充；失败不替换目标对象。`GameResources::open_std` 接收场景数据，TH14 的 `EclResourceProvider::parsed_ecl` 提供已解析文件。`EclProgram` 保留已有包含顺序、重复定义插入和二分查找行为，只把已验证文件接到同一个组装函数。

首次生产入口对照虽然 42 组字段／字节相同，仍发现四面 `st04mbs2.ecl` 和 `st04bs2.ecl` 各六次回主线程解析，共 12 次遗漏。当前 worker 按实际 ECL 包含表补齐依赖，保持请求项顺序并为补充项提供单独的有界响应；传输去重不改变程序组装时的重复读取和插入顺序。响应校验名字、类型、所有者与数量，取消后的数据仅交给失效回调释放 token。

补齐后相同 42 组中的遗漏为零。不存在按关卡号补写特殊清单，四面的额外名字来自文件自己的包含表。测试中的普通同步入口继续可用；声明拥有批次的包发生错误时明确失败。

## 候选与未闭合项

基线为 `7d490039fea57057995d7902e325bb45ec355823`。接口／头文件修改后完整重编 146 个单元；包含闭包仅改变独立 worker 与消息交付，第二次构建核对复用全部 146 个主模块对象，主 Wasm 逐字不变。主 Wasm 2,743,750 字节，SHA-256 `4bbd1e4ff36fc2bd55ec2b38f3ded74e7fdffbad129687b0b3789fa8395811cd`；worker Wasm 76,918 字节，SHA-256 `217c46f4b367a106affb34acdd8a20b2f37576a5546da37f12a89638de39f38d`。139 路由／27 项 HTTP 通过，既有生成字体／音乐资源继续复用。

实际服务的主模块／worker 字节与上述构建相同，父页及游戏页均注入本机静音策略。Chromium 156／Windows 已从普通 Replay 用户页选择咲夜 B Hard 四面，观察到关卡运行、暂停及恢复；另对保存的 Normal 灵梦 A 717 帧片段核对自然结束及返回列表，证据绑定见[机器复核摘要](th14-stage-ecl-worker-verified-oct29.json)。该浏览器观察不代替全局像素或内部状态比较。
