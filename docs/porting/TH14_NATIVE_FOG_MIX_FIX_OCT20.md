# TH14 片元雾混合修正 · 2026-10-20

仅 TH14／version10 改变片元雾混合表达式及雾颜色上传：雾颜色各 RGB 字节乘 float32 的 `1/255`，纹理因子继续原有除法归一化；用 `rest = fog - fog * factor`、`color = source * factor + rest` 取代原 `mix(fog, source, factor)`。顶点矩阵／雾因子的前次修正保持，共享着色器头和玩法、音频、存档源码不变。没有按坐标、帧号或关卡填补输出。

在相同 21 幅记录的直接绘制场景上，完整颜色通道差 **18→1**，最大差仍为 1，完全一致整帧 **11→20**。每幅差异数量未增加，也没有新增差异通道。唯一剩余：三面第 1199 帧 `(144,373)` 的蓝色通道，Portable 119、Native 120；它仍保留，未以容差记为通过。

## 原生公式发现与独立控制

实际安装 D3D9 HAL 向 RGBA32F 目标绘制，保持所有顶点 eyeZ 相同、投影深度单独固定。先将 8 组声明的 source／fog ARGB8 颜色与之前的 240 个雾输入交叉，共 1,920 例。最初同时使用除法或同时使用乘法归一化的八种表达式全部失败，报告原样保留。随后比较独立 source／fog 归一化与六种混合顺序，发现以下模型的全部 5,760 个实际 Native RGB 字一致：

```text
source = float32(sourceByte / 255)
fog    = float32(fogByte * float32(1 / 255))
rest   = float32(FMA(-fog, factor, fog))
result = float32(FMA(source, factor, rest))
```

这是观察后提出的假设，单独标注。再在读取 GPU 结果之前冻结新输入：24 组确定性生成的新颜色对、两组新 near／far 范围、边界邻居及负 eyeZ，共 1,200 例。上述模型预先列为检查条件，3,600 个新的 Native RGB 字全部一致，其他候选仍有差异。两组共 9,360 个 RGB 字一致，alpha 另检查为 1。实际读取的原始字、输入及生产脚本哈希保留，没有用模型输出覆盖 Native 结果。

这验证了本机固定功能算术模型。GLSL ES 的表达式并不承诺所有驱动以完全相同方式融合；Web 侧结论来自实际浏览器完整帧比较，不能把 Native 的标量控制当成 Web 每个浮点中间结果或任意硬件的证明。
