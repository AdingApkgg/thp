# TH14 Player 初始化与空速率时钟

2026-11-13。本次修正 TH14 的两处行为：Player 的 transition 时钟在关卡激活前保持全零／空速率指针；`Timer.tick()` 遇到空速率指针时按 1 推进，保持指针和标志不变。其他作品保留原路径，`Timer.advance()` 本次未修改或验收。

## 原版与首差

新 Oracle 执行完整原版 `44c350` 构造与 `44c4a0` 初始化，使用六种自机各自实际 ANM／SHT。ANM 资源经过实际原版加载／模板准备；初始化中的 ANM9 请求是返回该资源的缓存服务。文件字节、CRT 分配／memset、纹理创建／尺寸查询为声明边界，Player 初始化、SHT 解析、嵌入 ANM 更新和注册插入执行原版代码。没有启动原版 Windows 游戏进程。

原版构造最后清零整个 `0x184c0` 字节对象，发布 Player；初始化注册 Main18／Draw28，启用位仍关闭。六组完整构造／初始化均无 RNG 写入。C++ 与原版比较每组 41 个所选状态／时钟／RNG 字、160 个规范 SHT 头字及嵌入动画的 303 字表示，共 3,024 字。此前 C++ 把 transition 时钟提前初始化，六组各有 previous、rate-present、flags 三字段不同，共 18 字；修正后全部一致。这不是整个 Player 对象逐字节验收。

第一轮错误地直接比较原版紧凑 SHT 头与 C++ 扩展头，产生 501 个差异，结果保留并拒收。规范映射由实际解析器给出：前 40 字节保持，原版 `0x40..0xdf` 的 20 对选项坐标进入 C++ 数组，其余 52 对为零，原版 `0x28..0x3f` 移到六个 native-extra 字。修正映射后只剩上述 18 个真实时钟差异；没有据错误比较修改 SHT 数据或解析器。

## 空速率语义

原版完整 `408690` 明确检查空指针，空时走加 1 分支，不写速率指针或 flags。原版执行器的零页保持未映射。240 组输入覆盖空／有效指针、阈值两侧、零／负速率、NaN／无穷、四种时钟状态及四种 flags；C++ 另换四种 Wasm 零地址哨兵，共 960 次、4,800 字比较。旧实现有 64 次失败，有效指针路径零失败；新实现全部一致。旧源码对空地址解引用还允许优化器作非空推断，不能依赖 Wasm 零页恰好存了什么。

TH14 Player 构造现在保留该空时钟，实际 `start_stage()` 仍在对应原版 `44cc10` 的位置绑定速率。新空指针分支仅用于 TH14 tick；没有改共享速率的原子读写、非空速率数学、加载等待、随机种子或调用数。
