# TH14 实际 Vorbis 解码、寻址与循环 · 2026-11-13

此前线上 18 首 Vorbis 的时长只经过 FFprobe 元数据检查。本轮用当前 `59a8cc4c` 的实际 `AudioDevice.cpp` 及其原样包含的 miniaudio、stb_vorbis、`Th14MusicStream` 构建独立正常权限 WASI 探针，补查实际解码路径。没有改动生产音频代码，也没有打开输出设备。

探针在 Arch 上读取当前正式包复用的 18 个 Ogg，逐文件核验发布哈希，确认走 Ogg 而非 FLAC 回退。格式输入是实际 `thbgm.fmt`。每首都实际解码到末尾，与独立 FFmpeg 的整个 float32 输出按采样位置比较：共 99,457,880 个立体声帧、198,915,760 个样本，长度与原版格式表相同。执行前固定容差为每样本绝对误差 `0.0001`，实测最大 `0.0000006556510925292969`，超阈值样本为零。两个解码器的浮点输出并非逐位相同，不能称原版 PCM 完全相同。

随后通过实际流式适配器在每首的开头、原版 intro／loop 点和尾部各寻址一次，共 54 个 128 帧窗口；输出与同一解码器的完整顺序结果逐字节一致。每首从原版末尾前 64 帧连续读取 192 帧，末尾 64 帧接 loop 点 128 帧及返回游标均正确、逐字节一致。18 个偏移一帧的负控制都能检出差异。

首次夹具在关闭第一首后同时清空格式表，导致第二首测试前失败；该失败报告保留。修正夹具的多曲生命周期后完成全部 18 首，生产函数没有修改。另一次 C++ 夹具缺少标准头的编译失败同样保留。没有重新编码音乐，没有将音乐或原始 PCM 复制到 Windows，也未保存解码音频；只传输小型探针及格式元数据到已有音乐所在的 Arch。

这是独立 WASI 解码／寻址／循环检查，使用当前源码中的真实函数，不是直接运行正式浏览器 Wasm。浏览器异步播放、首次切歌卡顿、Continue 的跨曲地址分支、完整 DirectSound／miniaudio 混音、最终 PCM 和硬件延迟仍需另验。
