# TH14 RNG 内部的初始化交付

动画指令之间的轮询仍不能表达原版 RNG 读取种子后、写回之前发生的 worker 恢复。本次在 TH14 的 RNG 事务内部增加通用语义检查点：读取前、读取后、计数更新后、写回前和写回后。计数更新顺序及返回的缓存结果按原指令执行；Rng 仍占八字节。作用域覆盖动画预更新、指令和后更新，并恢复嵌套调用的上一个观察者。初始化轮询复用既有 GameSession 回调，不新增原版种子、VM 字段或推进次数输入。

实际原版灵梦 B Normal 的新受控采样完成 34,000 回调。主线程在 `403373` 写回前保持已计算的 CX，worker 自行执行原始 Sleep、种子恢复和全局复制，再恢复主线程。`403376` 观察到缓存值覆盖了刚恢复的种子。两线程均只增加一次自身挂起计数并恢复原值。原始返回链 `4034bc / 40b209 / 46ff21` 确认这次来自 ribbon 预更新；不据此推定 VM 的文件、脚本或实时注册身份。

候选核心在该受控时点下，所选状态、相机、HUD、982 行 VM 的全部 303 字段、注册表顺序、318 个战斗检查点及初始 3,275 次发布全部严格相同，独立检查器从原始载荷重新核对通过。此前子动画指令中的另一条 34,000 回调受控记录也保持严格及独立通过，覆盖 956 行 VM／322 个战斗检查点。

原版 RNG 的 800 组受控指令组件对照覆盖 16／32 位事务、开启／关闭临界区、五种交付边界和调用计数回绕；当前源码重新编译的 Wasm 全部通过。初版只覆盖关闭临界区；扩展后检出 40 处开启模式的 16 位返回值错误，已补齐“关闭时返回缓存 CX、开启时退出临界区后重读 seed”的区别，初版及其失败保留。错误地把“写回前恢复”移到“读取前”的 144 组输入被检出；嵌套观察者的生命周期、失败及重入控制通过。TH12／13／14／16 的 12 项相关语法检查通过；其他标题保留原有 RNG 路径。

原版十条首个 Player 前的首次异常通知完整保留，仅验收此后暖启动前缀，异常原因和冷启动仍未证明。旧 36,826 回调的独立交错记录继续严格失败：种子／计数分别有 14,403／1,702 处差异，活动 VM 719 处、战斗字段 488 处差异；现有粗粒度时钟记录不能证明当时的精确交错。不得用新受控样本覆盖这项失败。
