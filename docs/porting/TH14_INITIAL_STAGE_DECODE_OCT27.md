# TH14 初次关卡分段解码与回调生命周期 · 2026-10-27

初次关卡加载现在先完成自机 file 9 的上传、创建自机和选项，再按场景、HUD、时间线及各个 ECL ANIM 依次解码和上传。原先在自机创建前同步读完所有关卡资源的路径已拆开。每个 ANIM 在前一项上传返回后才读取，不预设加载时长，也不改动画年龄、RNG、录像或图像。

这是异步回调边界的实现。当前浏览器执行模型仍没有复现原版并行 CPU 解码线程；测试宿主也明确将回调执行时长声明为零。因此本项不声称已关闭实际原版游戏帧中四个光球的 5／6 拍年龄差。

## 实现范围

`StageResourceEffects` 增加默认关闭的初次延迟解码选项。SDL Application 启用后，`GameSessionResources` 先发布一个稳定地址的空关卡资源所有者，上传选中的自机。其余无图形调用方继续使用原有同步加载。

初次 worker 在 file 9 返回后创建自机，再读取场景／背景、所选 HUD 对话、时间线定义和各个 ANIM。回调保存任务种类、索引和 generation，暂停后旧回调只释放自己的 token；恢复交还原待执行任务。取消资源所有者时先撤销这些回调，随后才释放资源。

GameBattle 为自机而提前构造时，时间线还不存在。现在在初始化战斗、资源齐备之后重新绑定 ECL 动画所有者，避免早期空绑定被沿用。首版在 Application 2085 帧触发的 ECL 303 失败原样保留；修正后的两个后端均通过同一窗口。

42 组直接比较 ANM 纹理声明／像素／精灵／脚本、STD 对象／实例／指令、ECL 原始字节／子程序定义／包含文件／boss 程序及所选对话，不以汇总哈希代替字段和字节比较。测试档案保持只读，原始 DAT 缓冲在 Archive 借用期间保持存活。

演示两后端的状态、活动 VM、画面、文件和各 1,508,352 帧静音 PCM 相同；普通回放前缀对应为各 374,784 帧静音 PCM。与修改前同输入演示比较时，游戏状态和时钟仍相同，回调交付计数因新增解码任务而变化，记录中保留这些计数。实际队列观察为 file `9 → 4 → 6 → 10 → 11`，自机在首次场景读取前已存在。

两种暂停控制均经过实际生产 worker 的暂停／恢复方法：共 2,269 个外部时钟帧、2,264 次实际 Application tick，恢复后的两组 RNG、339 个活动 VM 各 303 字、完整图像、文件和静音 PCM 与未暂停基线相同。此测试没有操作桌面、物理键盘或真实音频设备，不作为普通用户界面验收。

所有 141 个核心单元先完整重编；随后绑定修正只重新编译 GameBattle，并核对复用其余 140 个对象。两后端均执行实际生产 Application／渲染／字体／音频设备，默认静音。原有无关 ResourceCrypt 工作区修改继续隔离，使用已发布的同一份源码。

## 仍未通过
