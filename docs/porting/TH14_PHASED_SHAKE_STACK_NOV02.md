# TH14 分阶段震屏留下的控制器栈字

2026-11-02。修复 `ScreenShake.cpp`、`ScreenShake.hpp` 与 `NativeStackTh14.hpp` 中此前标为未知的分阶段震屏路径。范围与哈希见 [证据](th14-phased-shake-stack-nov02.json)。

普通震屏 `46cda0` 与分阶段震屏 `46cf60` 的调用栈相差一个保存的 EDI。相同的回调入口栈位置减 56 字节，在普通路径上对应原版 RNG 调用内、固定版本 `RtlLeaveCriticalSection` 保存的 ESI，即脚本 RNG 对象地址；在分阶段路径上对应其保存的 EBX，即最后一次 `next32` 返回值的低 16 位。相邻的减 60 字节位置才保存 visual RNG 对象地址。

新的静音原版魔理沙 A Easy 采样在第 18,115 个 Player 回调处实际观察了分阶段回调入口、栈写入、第二次 RNG 返回与原回调返回。三个边界中的低 16 位逐字相同；实际模块表与本机 32 位 ntdll 的哈希、指令相符，回调入口／返回的 ESP 关系也吻合。观察器仅增加硬件断点和只读记录；内存写入、显式线程暂停／恢复、调试上下文及终止调用的 AST 与基线相同。音乐和音效配置及实际主音量均实测为零。

该采样在完成目标观察后按计划结束，观察器退出 1，保留为诊断前缀。它没有证明整条录像结束，也没有执行随后另一自机的 Bomb 控制器读取。

发布检查检出了生成观察器时重复转换的 Windows 换行。发布文件仅规范换行，原始采样源码原样保留；检查器同时绑定两份哈希，并要求规范化后的字节及完整 AST 相同。既有原始采样记录未重写。

原版组件实际执行震屏、计时器、RNG 和完整固定 DLL Leave 路径，共 2,016 组输入。临界区获取、无追踪表的 TEB 和回调栈是声明的组件环境。有随机调用的 480 组与实际 C++ 比较了 5,280 个字；旧实现的 192 组未知栈结果修复后全部一致。192 组相邻栈位置控制均被拒绝。其余 1,536 组原版非随机分支记录保留，不算本项 C++ 栈比较的通过。

实现保留最后一次实际随机返回值，再对它取模生成震屏偏移；在原调用位置把低 16 位传给既有栈数据模型。该值来自当前引擎自身的 RNG。没有使用采样中的原版随机数、指针或推进次数。

全部 141 个核心单元重新编译，隔离候选的 16 份自然回放、1,579,705 个捕获回调均通过严格及独立原始载荷复核；另有 12／13／14／16 四个作品的八项编译检查。正式产物与已验证候选逐字节相同，134 个普通导出一致。当前源码另行重编的组件仍通过全部 480 组。此前完整图形回归只属于旧核心；新核心的 Application 与浏览器需要单独验收。
