# TH14 GLES 近裁剪与齐次视口修正

2026-11-05：正式 C++ GLES 渲染器的 85 组完整像素缓冲、共 104,448,000 字节与独立 D3D9 HAL 指令组件一致，差异为零。旧正式渲染器在 21 个保留 Stage 场景中有一个蓝色通道字节不符，本次在相同组件参考下归零。**这是有限图形组件通过；整作 1:1、原版整局 framebuffer 和当前浏览器 UI 尚未验收。**

## 改动

仅修改 `portable/sdl/Renderer.cpp`、`Renderer.hpp`、`Shaders.hpp`、`Th14RenderMath.hpp`。TH14 的 `WorldUv` 非索引几何在跨越近面且含非正 W 时，C++ 保留原始边端点并确定裁剪拓扑；GPU 使用自身倒数、分别舍入的两个权重和 nearest-even 乘积计算交点、UV 与雾值。四边形按实际原生 solid-fill 对照确定对角线，包含镜像条带。

参考同仓库 TH143 的 `ClipTrianglesToHardwareV4.mjs` 和 `FloatMultiplyNearestV2.mjs`。使用一般几何、浮点和拓扑规则，无按帧、坐标或像素值补丁。内部绘制以显式参数标记，不能由外部顶点步长误触发。异常数值、不支持的布局、索引、雾模式或远面相交沿用原绘制；WebGPU 的入口保持原路径，其运行效果没有继承本次 GLES 结论。

正式路径保留原始整数视口和齐次 W，交点计算后补半像素偏移。早期候选将坐标映射到二次幂视口，虽然通过保留场景，却在额外合成投影中产生 17 个通道字节错误。扩大实际渲染目标后错误不变，不能把根因归为目标尺寸。六组齐次运算对照中，原视口两个版本通过；四个二次幂版本仍失败。原生小数视口仅用于诊断，正式代码不使用原生视口干预、回调修改或额外 framebuffer。
