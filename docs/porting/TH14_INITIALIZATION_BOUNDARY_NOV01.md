# TH14：加载初始化在子动画首次更新前交付

2026-11-01。生产核心新增初始化边界轮询，整作 1:1 未完成。

旧实现只在 Supervisor、正常动画注册表入口和顶层 VM 返回处推进加载。原版 worker 可以在父动画执行期间恢复下一关的 Replay 种子；如果子动画的首次更新先消费了随机数，再在父动画返回时恢复种子，后续动画状态就会不同。

这次在新的原版运行中明确控制两条线程的交付顺序：二面第 13,919 次 Player 回调后，主线程停在 `47ef1e` 的真实调用指令，子动画为文件 2／脚本 16，父动画为文件 2／脚本 17。子动画已经复制模板和绑定父级，句柄仍为 0，首次更新尚未执行。worker 随后执行自己的 Sleep 60ms、Replay 恢复和全局复制。没有给原版补写种子、计数器、指令或输入；两条线程各只增加并归还一次暂停计数，单次暂停上限为两秒，暖启动仍只有一次声明的 attract 位清除。

这是受控诊断。它提供新的真实初始化边界，不能回填为旧另一份 80,324 回调记录的内部指令证据。

## 生产修改

`AnmManager::create` 在模板、位置和父级设置完成后，首次脚本更新前通知 Session。此处只轮询已经启动的 worker 初始化，不推进 HUD、场景、时间轴或资源替换；资源阶段留在原有常规加载轮询中继续执行。初始化先标记阶段，保证嵌套调用不会重复恢复种子；失败沿原有错误路径返回。生产代码不含目标文件／脚本／回调号、原版 RNG 数值或补偿次数。

测试夹具只在实际观察到的子动画边界交付宿主时间，由生产加载器从自己的 Replay 恢复状态。比较驱动保留原有全部严格断言，新增内容仅登记该时钟及检查交付状态。
