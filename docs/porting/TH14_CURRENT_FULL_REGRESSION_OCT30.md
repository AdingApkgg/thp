同一生产核心的实际 C++ Application／Renderer，以普通归一化菜单输入从冷标题选择完整咲夜 B Hard 录像。当前 GLES 二进制重新运行 123,412 帧，全部 25 项动作和 44 项断言通过；六面的实际战斗时钟分别重置并前进，音乐索引依次为 1、3、5、7、9、11。第 123,352 帧自然进入回放结束菜单，残机 1、内部得分单位 154,806,314（显示分数 1,548,063,140），随后稳定 60 帧。

[独立验证器](../../tools/th14-current-ordinary-full-evidence-oct30.py)核对实际终态、全部动作、六次激活、八份完整 BGRA 输出、141 份生产源／对象、二进制、声明的进程 cookie／初始时钟，以及实际文件。完整录像的 110,306 字节前后不变。实际静音 sink 处理了 90,553,344 帧 PCM；保存其累计哈希，没有独立保留整段原始 PCM。[证明元数据](th14-current-ordinary-full-oct30.json)绑定本次运行，不沿用以前的完整回放结果。

该入口使用声明的 SDL／WASI 平台服务、原生 GLES 设备及静音队列，archive-worker 功能关闭。所选结束分数和残机与录像头及声明的原版暖启动记录一致。八份图像是本次输出，尚非原版普通 Application 的整幅画面比较；物理音频、当前浏览器与 IndexedDB、完整原版普通界面和全部模式仍未验收。

本次并行 WebGPU 运行在原定 3,600 秒墙钟上限处失败，止于 108,875 帧、六面。六次实际战斗激活已经观察到，自然结束仍未观察到；严格验证器拒绝产生通过文件。[预算失败元数据](th14-current-full-budget-oct30.json)保留原错误，不改变上限，也不将其归类为已证明的玩法错误。旧日志记录的 GLES 全程约 20–22 分钟、WebGPU 约 66 分钟，因此当前优先完成较快后端的全流程，再单独解决 WebGPU 与浏览器范围。

## 魔理沙 B Normal 的另一份原始输入

新取的完整 `th14_ud000b.rpy` 经原版 x86 解码和独立字节复核，文件头包含六面。原版暖启动的实际运行却在三面自然 GameOver，33,926 个回调；当前核心完整复算该实际范围，所选状态／相机／HUD、983 行 VM 各 303 字、362 个战斗检查点和初始 1,754 次发布顺序严格一致，见[有限范围证明](th14-marisab-normal-alt-oct30.json)。这次没有补齐六面，30／25 清单不增加。

进一步核对确认：现有暖启动观察在首个 Player 仅清除 `0x40` 演示位，原版运行标志成为 `0`；普通 Replay 使用 `0x2`，原版 `0x435ed0` 据此跳转到 `0x456050` 执行完整恢复。新输入暖启动的首个 Player 中，玩法 RNG 已与录像头种子一致，动画脚本 RNG 仍保留另一启动种子。暖启动的相等结果保持原范围，不能代替普通入口。尚不能据此唯一归因任何旧失败。

[thprac 的实际源码](https://github.com/touhouworldcup/thprac/blob/master/thprac/src/thprac_th14.cpp#L699)也记录魔理沙激光相关的栈值，并按关卡、帧和序号回放；其钩子 `0x45286f` 对应当前虚拟栈模型已观察的原指令。现有五份缺覆盖输入的完整 USER 记录均不含这种恢复记录。本次仅参考源码，没有运行补丁或向原版／移植版传入修复值。
