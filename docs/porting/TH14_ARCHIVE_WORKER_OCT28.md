# TH14 浏览器首关后台解压接入（2026-10-28）

首关加载现把归档解密／LZSS 解压交给独立 Web Worker 和独立小型 C++ Wasm。主线程继续运行现有 Application、解析 STD／ANM／ECL 并上传 GPU。原始 DAT 由主游戏保有，worker 收到独立副本；输出使用独立转移缓冲。没有共享解压字典、伪造固定帧等待或修改 VM 年龄。

ECL 解析后才能知道 ANIM 文件名，因此时间线规划和随后 ANM 解压按实际依赖分开派发。解压请求不占用主 Wasm 的 Asyncify 队列；结果准备好后，交付回调仍串行进入该队列。缓存仅在所属回调内可读。取消后的旧回调照常交付，让 C++ 的代际检查释放 token；旧数据不会进入新关卡。失败批次显式报错，未列入批次的读取仍使用原有同步归档路径。

浏览器构建明确启用 `TH14_ARCHIVE_WORKER`。现有原生测试宿主不启用它；重新编译的 GameResources 和 GLES Application 对象分别与原冻结对象字节相同，原生 WebGPU 的五个单元也重新编译并成功链接，未增加后台归档导入。既有原生完整录像仍保持其冻结版本范围。

验证范围见[哈希绑定报告](th14-archive-integration-verified-oct28.json)：

- 独立解压器当前构建的 227 个归档条目、253,480,939 字节，与独立同步实例直接比较一致；反向顺序另按保存摘要核对。
- 实际生产 Runtime、client、endpoint 和浏览器 worker 源码在 Node 消息适配器下完成帧栅栏、错误、取消、旧回调清理和恢复控制；这个帧栅栏是组件输入，不是实际浏览器 GPU 帧的跟踪。
- 真实浏览器 GameResources 对象与独立 CPU worker 合作，7 关 × 6 种自机选择共 42 组解析值／字节对照通过；534 次读取使用后台缓存。失败批次不能悄悄回退为同步成功。
- 最终浏览器候选重新编译全部 146 个 C++ 单元；主 Wasm 2,721,058 字节，小型 worker Wasm 25,105 字节。139 条静音预览路由和 27 项 HTTP／Launcher 检查通过。约 415 MB 已生成字体／音乐沿用不可变别名，没有复制原版数据文件。
- 在实际浏览器普通入口观察到启动、Normal 灵梦 A 选择、首关、暂停、恢复及移动；保留七份完整截图、可访问性文本和加载日志。主程序和 worker 的实际服务字节另与构建摘要核对。

这仍不是整作 1:1 或完整浏览器验收。原版普通游戏首帧的严格 VM／像素差、不同启动历史下的动画 RNG、完整模式覆盖、浏览器录像保存读回及完整浏览器流程继续开放。后台解压只接入首关加载的已知归档依赖，不能把有限 UI 观察或组件并行性视作原版调度等价。

本轮旧候选和失败的工具构建日志保留；最终候选在 `artifacts/th14/native-frame-readback-oct28/worker-runtime-delivery-v2/`。所有测试及预览维持静音。
