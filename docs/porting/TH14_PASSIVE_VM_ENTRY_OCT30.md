# TH14：原版待送达 VM 入口与有限时钟对照

2026-10-30。只推进 TH14，整作 1:1 未完成。

本批修正的是原版采样器的调试事件收尾，并补充时序诊断；生产玩法、RNG 算法及 Wasm 未改。

## 原版采样器

原版 worker 在 `456133` 恢复 Replay 种子时，主线程可能已停在 `47e65b`，但入口调试事件尚未送达。此前采样器在没有已登记活动调用时立即撤下窗口，随后入口事件触发断言。保留了这次 13,936 回调的观察器失败，没有将其记为原版正常结束。

现在保留入口／返回观察点，依次处理待送达入口和真实返回，再关闭窗口；原有待送达返回分支不变。旧返回顺序与新入口顺序的真实处理器 AST 控制均通过。未增加线程暂停／恢复调用或原指令、RNG、计数器写入。仍仅保留声明过的一次暖启动 attract 位清除。

独立新采样实际达到声明的 33,000 回调上限并主动结束，覆盖两个 worker 窗口、4,714 条调用边、2,357 对调用／返回，每条边读取 1,484 字节 VM。三面实际遇到并处理了一次待送达入口。两个恢复时点均没有已登记活动 VM，因此不声称恢复发生在某条 VM 内部指令；较晚调用边的字节不回填为恢复时刻的内存。

原版退出正常、观察器报告无错误；命令返回 1 是该历史工具只把自然 Replay 结束视为成功。本次达到预声明前缀上限，属于有限采样，不是整局通过。原始报告旧字段误写 `diagnosticPrefixOnly=false` 已保留；检查器按实际终止边界判定前缀，生产器今后按 `not complete` 填写。

## 当前实现的时钟诊断

同一当前 `57a5441` 玩法核心、同一暖启动 Wasm，未补正常动画入口时钟的 33,000 回调对照严格失败：种子字有 2,004 行差异，调用次数字有 28 行差异。相机、HUD 和本段 321 个战斗检查点一致；末尾 VM 状态仍不同。这个失败完整保留。

只读跟踪重编一个动画管理器对象，复用 140 个对象。1,006 行轨迹与未跟踪运行的 333 份共同游戏载荷逐字节一致，无溢出。轨迹明确显示：基线在 NORMAL 注册表更新结束后、OVERLAY 更新开始前才恢复种子；NORMAL 中加载动画创建的子动画已消费 24 次随机数。因此撤回“这份样本证明恢复发生在嵌套 VM 调用内部”的推测。

新原版采样在三面主线程首个正常 VM `9/35` 入口待送达时观察到 worker 恢复；该 VM 与模型注册表头身份相符。将这个外部完成时间投影到**已有生产正常动画注册表入口**的时钟夹具后，32 字所选状态的全部 33,000 回调、303 字活动 VM 快照、战斗检查点、25 字相机、两字 HUD 及初始 2,870 次发布全部一致。夹具只交付宿主时间，不传入原版 RNG、VM、句柄或画面作为游戏运算值；原比较器的严格检查全部保留。

这是诊断投影：原版注册表入口的精确墙钟没有被观察，调试事件暂停也会影响时序。它证明已有入口轮询能够处理这一份交付次序，不是独立线程调度验收，也不关闭旧 80,324 回调原版样本对应的 48,000 回调失败。
