# TH14 无纹理绘制的反馈回路与加载 RNG 调用者 · 2026-11-13

在复查 Goan114 的新提交 `19170e47016e10d61d5e69556989b68b5cdea8e3` 时，实际 GLES 小范围对照发现当前渲染器自身的一个问题：无纹理绘制只更新 `hasTexture=false`，没有解绑上一次采样纹理。该纹理再次作为渲染目标时，通用 shader 仍保留活动 sampler。

OpenGL ES 3.0.6 §4.4.3.1 规定，条件执行的采样指令也属于反馈回路判断范围：[Khronos 原始规范，第 211 页](https://registry.khronos.org/OpenGL/specs/es/3.0/es_spec_3.0.pdf#page=224)。本次在 `PORT_TITLE == 14` 的无纹理绘制分支显式选择纹理单元 0 并解绑纹理，避免让之前的渲染目标继续被 sampler 引用。其他作品保留原分支。此修正独立于协作者的延迟颜色清屏优化；该优化本次未合入生产源码。

实际 ANGLE/D3D11 离屏 GLES 验证 64 个清屏、覆盖、深度、复制、采样和提交序列。未修正版本有两组重复采样序列整张 32×32 图像为零，而相同序列前一次为 `0x7f28c47b`。解绑后，两组都严格得到该颜色，64 组无重复序列差异。TH12、TH13、TH16 的三个实际渲染对象逐字节不变。原失败、无效准备、测试边界错误及后续改正均保留，未把候选与基线同字节的一次无效构建计作通过。

当前正式浏览器构建仅重编一个 Renderer 单元，逐项核验并复用其余 145 个对象；369 个构建源码绑定仍逐项检查。Wasm SHA256 为 `f4026156b7449c8186fb0c6b4c77a46024451eb79b9078fac39faa3c77e3dd5a`。SDK Application 的 145 个正常权限提供者中重编一个宿主 Renderer，复用 144 个已验证对象，夹具单独允许观察所需的访问权限。普通菜单进入灵梦 B Normal，在 542 个宿主帧后到达首个 Player，静音、无异常、全部已测资源回收。没有比较该次原版整帧、整关、普通存档或浏览器 UI。

该次有限开局还保留了 ASCII16 的 1,560 条 RNG 调用边界记录，覆盖 65 次初始化调用，每次 12 个 Next32、计数增加 24。记录时 VM 尚未取得发布后的 ID，不能把这 65 次调用当作已证明的 65 个独立对象身份。以每次实际记录的入口 seed/count 为相同输入，执行未改写的原版 ASCII16 脚本和 `46fe50` VM 更新函数，观察实际 `403310` RNG 调用与返回：全部 1,560 条记录的点位、脚本指令偏移、seed、count 相等。没有把任何原版状态反馈给正在运行的 C++ 游戏。

该 Oracle 的 cookie 与精灵选择是声明的服务边界，VM 初始几何使用组件默认值，未验证原版工厂、原版同条件普通开局、物理线程时间线或几何。它证明了已观察初始化的实际调用序列，而非仅仅检查 RNG 轨道终点；初始化何时多／少一次仍是开放问题。既有 24 次加载偏差、弹状态、相机、完整机体／难度、整帧、最终 PCM、存档与浏览器入口验收继续保留，`completeGame=false`。

补充审查：显式启用 TH14 分支后的未修正 Renderer alpha 测试 8,192 组与保留的原版 D3D9 像素相等；协作者新 alpha 阈值方案加解绑修正的独立候选也相等。后者完整命令在 alpha 完成后因寻找错误的基线目录而失败，报告仍保留失败状态；相同模块随后只补跑缺失的 64 组清屏比较并通过，没有重复执行已完成的 alpha。该独立候选未部署，不能把结果算成生产版本的整帧验收。
